# 公共测试自动化平台最终目标

本文件是公共平台完成度的验收权威；项目业务交付仍由各项目适配器自己的范围、收据和清理门禁决定。

## 完成条件

平台只有同时满足以下条件才可标记 `complete`：

1. 参考系统基线满足 `planned = executionEligible + classifiedExclusions`、`executionEligible = executed`、`executed = passed + failed`，且逐用例收据、断言、操作、清理和证据完整。
2. 公共实现、项目适配器、执行授权、检查点恢复、失败分类、审计哈希链和报告绑定均通过系统无关契约测试。
3. 至少一个跨方案试点和一个不同 `applicationId` 的跨应用真实试点通过当前实现指纹、上下文和证据门禁。
4. 最终裁决、评审队列和外部依赖状态均由当前证据生成，禁止用历史摘要、汇总计数或截图替代逐条收据。

当前仓库没有真实项目适配器和跨应用目标系统，因此只能完成公共平台实现与合同验证；`npm run verify:system-test-platform` 必须保持明确的 `FINAL_GOAL_NOT_MET:PROJECT_ADAPTER_REQUIRED`，不得将平台未完成误报为业务模块失败。

## 变更验收

任何公共流程变更都必须补齐公共合同、适配器接入合同和系统无关负向测试；报告格式、边界和门禁验证使用隔离或合成产物目录，不因验证报告而重跑业务用例。
