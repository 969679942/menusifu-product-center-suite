# 业务规则生命周期治理

## 目标

业务规则是 PRD、测试方案、测试用例、自动化绑定和执行证据之间的稳定中间合同。平台允许执行结果形成观察候选，但禁止执行成功直接覆盖正式业务规则。

标准流程：

`PRD/人工确认 -> 规则候选 -> 指纹绑定审批 -> 正式规则 -> 候选用例 -> 自动化绑定 -> 执行收据 -> observed 候选 -> 人工评审 -> 新规则修订`

## 核心字段

| 字段 | 中文含义 | 必要性 |
| --- | --- | --- |
| `ruleId` | 规则的稳定唯一编号；规则修订时不变 | 必须 |
| `ruleType` | 规则性质：规范规则、运行观察、UI/API 合同、技术约束或延期规则 | 必须 |
| `statement` | 人能直接理解且可判断真假的规则陈述 | 必须 |
| `scope` | 规则适用的应用、业务域、实体、操作和渠道 | 必须 |
| `sourceRegistry` | 规则引用的 PRD、人工确认、审计或执行收据清单，包含精确定位和来源指纹 | 必须 |
| `sourceFingerprint` | 整个来源登记的稳定哈希；用于识别来源、定位或验证状态漂移 | 必须，自动计算 |
| `ruleFingerprint` | 规则行为语义的稳定哈希；用于精确判断哪些用例和绑定需要重验 | 必须，自动计算 |
| `effectiveVersion` | 规则从哪个产品或发布版本开始生效 | 正式规则必须 |
| `effectiveContext` | 生效环境、租户、角色、语言、路由和功能开关 | 必须；无约束时使用空集合，不得猜测 |
| `supersedes` | 当前规则替代的旧规则 ID | 有替代关系时必须 |
| `conflictsWith` | 尚未解决的冲突规则 ID；非空时禁止进入正式生成 | 有冲突时必须 |
| `linkedCaseIds` | 由该规则约束或验证的规范用例 ID | 生成测试时必须 |
| `linkedBindingIds` | 对应自动化实现或技术绑定 ID | 自动化生成和执行时必须 |
| `approval` | 人工审批决定、审批人、时间、理由，以及绑定的规则和来源指纹 | 正式规则必须 |
| `verificationStatus` | 草稿、待评审、已验证、需重验、冲突或延期状态 | 必须 |
| `revision` | 同一 `ruleId` 下不可变修订序号 | 必须，自动递增 |
| `previousRuleFingerprint` | 上一修订的规则语义指纹 | 修订时必须 |

## 生成语义

仅有自然语言 `statement` 不足以高准确率生成测试。生成前还必须有：

| 字段 | 中文含义 |
| --- | --- |
| `preconditions` | 执行前必须成立的业务状态和数据条件 |
| `entities` | 被操作和被验证的业务实体 |
| `actions` | 按来源顺序执行的动作，不允许排序重排 |
| `stateTransitions` | 操作前状态、触发动作和操作后状态 |
| `constraints` | 必填、范围、互斥、唯一性、权限等约束 |
| `outcomes` | 按来源顺序验证的主要预期 |
| `sideEffects` | 列表、下游、日志或关联实体等附带影响 |
| `assertionSurfaces` | 每个断言的字段、UI/API/下游通道、权威来源和终态 |
| `cleanup` | 清理策略是否已确认、是否需要清理及 API/UI 零残留要求 |

缺少前置条件、动作、预期、断言面、自动化绑定或已确认的清理策略时，规则可以登记和评审，但不得生成可执行用例。

平台通过 `buildBusinessRuleCompletionReviewQueue` 将这些阻断转换为字段级评审清单。清单只回显已有来源值，并区分纯元数据补充与可能改变规则指纹的语义补充。

## 审批与回写

- 正式审批同时绑定 `ruleFingerprint` 与 `sourceFingerprint`。来源漂移后，旧审批不得继续放行。
- `observed`、`technical` 和 `deferred` 类型不得通过自动化执行直接转为正式规则。
- 执行收据必须匹配规则、用例、应用和业务域，并覆盖规则声明的全部断言 ID。
- 规则包含 UI、API 或下游断言时，收据必须分别提供对应通道证据。
- 写入场景必须提供真实操作收据和完整清理终态；截图或运行汇总不能替代。
- 完整收据只会产生 `observed` 候选。候选经冲突处理、影响分析和人工审批后，才能形成新修订。

## 重跑原则

- 仅补充生成时间、展示文本或其他不影响来源/规则指纹的元数据，不触发重跑。
- 来源指纹变化会使审批失效，需要重新评审；若规则语义指纹未变化，不自动重跑已通过用例。
- 规则语义指纹或自动化实现指纹变化时，只把关联用例置为 `ready` 并执行精确重跑。
- 平台迁移、跨应用试点等通用成熟度工作不应阻断已满足自身门禁的模块交付。
