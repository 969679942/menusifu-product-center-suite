# 公共运行启动互斥

级别：必须。范围：public-core、project-adapter。目的：同系统两个活进程不得因 runId 相同而绕过启动门禁，也不得在门禁前覆盖共享编译产物或 flow 检查点。预期结果：冲突在编译、认证、造数及浏览器启动前拒绝；异常退出后能重新获取租约。后续影响：不重跑业务，历史通过事实保留；公共 runner 指纹会变化，当前候选重新校验。报告类变化对业务重验范围的影响仍由独立指纹审计处理。

`withSystemTestRunLease` 用项目真实目录和 systemId 派生本地 IPC 身份，runId 不参与互斥范围。当前支持 Windows 命名管道及 Linux 抽象 Unix socket；其他宿主明确返回平台能力缺失，不静默使用无效锁。端点不传输业务内容，连接立即关闭。操作系统在进程被强制结束后释放端点，不留下磁盘锁文件。

公共 flow 在写检查点、编译和审计启动前获取租约，顺序批次向 runner 传递同进程不透明父租约。父租约不进入环境、报告、检查点或业务授权；错误作用域、已过期及并发子调用均被拒绝。独立 runner 同样在 bootstrap 写入前获取租约。其他系统仍可独立运行。

旧版本未持有租约的进程通过 latest-run-state 补充拦截。runner 或已登记子进程仍活跃时保留 running；只有二者都不存在时才标记中断。冲突不覆盖活进程的报告、状态或编译合同。该检查不把 PID 复用判为进程死亡，可能保守阻断；它不证明未登记的外部进程不存在。

验证包括同 ID/不同 ID 竞争、其他系统独立运行、父租约生命周期、异常释放、真实子进程强制退出后恢复、真实 runner 的 bootstrap 前拦截，以及项目清单经公共 flow 的检查点保护。全部使用隔离本地夹具，不启动业务。

此合同不实现不完整批次内的逐案恢复、跨调用累计统计或分片调度；这些能力仍保持未完成。
