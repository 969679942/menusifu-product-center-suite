# 工作单元止损合同

适用范围：public-core。用户已要求建立每轮可见产出和token止损机制。

级别：必须。目的：阻止同一方向持续消耗而没有新证据或未决范围缩小。预期结果：每个工作单元记录目标、证据、问题集合变化、成本样本和后续决定。后续影响：仅限制下一工作单元是否启动；不改变业务状态机、用例资格或历史收据，不触发业务重跑。

可行性与成熟度：可复用现有目标token累计样本、不可变产物和公共执行意图；新增纯函数只裁定继续/暂停方向。它不能中断模型供应方计费，成本样本不可用时记录null，并仍执行时间与尝试上限。不得宣称实现了供应方硬计费限制。

执行代理在工作单元开始和结束采样，启动认证、浏览器或下一诊断轮前消费裁定。项目适配器验证证据文件的实际SHA256；状态报告不能作为新证据。公共函数检查未决问题净减少及新证据，两者任一不满足即暂停该方向，允许转向独立工作。恢复需新来源、诊断证据、授权或明确不同的有界问题，不能重置计数重复同一方向。

建议每单元上限：12000 tokens、20分钟、2次尝试。上限为可配置执行政策，不能自动补充目标总token预算。原始成本样本、输入和裁定必须保留；没有数据的token值不能写0。

验收：系统无关负向合同覆盖仅增加报告、范围扩大、无新证据、预算超限、未知token、计数回退。项目适配器用真实文件校验、缺失文件及指纹漂移合同证明接入。代理保存每轮裁定，任何失败不得以报告总数替代。
