# B端产品设计规范

> B端产品设计缺乏统一的标准和规范，当前以商品中心为基准，沉淀和梳理B端产品详细设计规范，确保体验与交互的统一；
> 
> 未来用于OFC订单履约中心、BOH商家后台、营销促销中台、组织机构、权限账号体系建设，以及其他相关B端产品设计；
> 
> 

## 一、产品设计原则

1. **一致性原则**

    1. 与用户习惯一致：场景、流程、逻辑保持一致，遵循用户习惯（语言、概念、操作等）；

    2. 各个界面保持一致：所有的元素、结构保持一致，如：设计样式、图标、文本、各元素位置等；

2. **反馈原则**

    - 操作即时反馈：通过界面样式变化（如按钮高亮、输入框提示）或交互动效，让用户清晰感知当前操作已被系统接收，避免操作不确定性；编码

    - 页面状态反馈：用户完成操作后，需通过页面元素变化（如加载进度、成功提示、数据更新）明确呈现当前系统状态，传递操作结果；

3. **效率原则**

    1. 简化流程：设计简洁直观的操作流程和页面信息；

    2. 清晰明确：语言表达清晰且表意准确，让用户快速理解从而作出决策；

    3. 帮助识别：界面简单直白，让用户快速识别决策而非回忆，减少用户记忆负担；

4. **可控原则**

    1. 尊重用户决策：根据场景可基于用户操作建议或安全/警告提示，但不能代替用户决策；

    2. 结果可控：用户可以自由的进行操作，提供一定程度的反悔操作，如撤销、回退、终止等；

## 二、页面设计原则

### 2\.1、表格表单类页面

1. 有多检索条件

    1. 展示顺序：默认按查询频率排序，同时遵循业务语义逻辑；例如 “商品名称→商品类型→状态” 的顺序，对应 “查询什么商品→是标准品还是套餐→处于启用 / 停用状态” 的业务逻辑；

    2. 折叠控制：当检索条件总数超过 N 个时，需区分 “默认展示” 与 “默认隐藏” 项；通常默认一行展示 3 个条件，整体默认展示不超过 8 个；超过 8 个时，超出部分自动折叠，用户可手动展开；

2. 表格数据预览

    1. 核心作用：多用于单据列表页与报表页面，需展示当页数据的小计与总计信息，为用户查看大数据量提供预判；

    2. 端侧差异：

        - B 端：侧重数据的集合与基础分析，满足业务统计需求；

        - C 端：在 B 端基础上增加丰富化展示，如卡片化呈现、数据概览图表化等，提升用户可读性；

3. 表格内字段列与操作设计规则

    1. **字段列展示顺序**：默认遵循业务优先级，常规顺序为：编码→名称→单位→类别→状态信息（启用 / 停用 / 禁售 / 下架 / 沽清）→数据信息（库存 / 价格）→时间信息（操作时间 / 新增时间）→操作按钮；页面信息过多时，需定义 “默认展示字段” 与 “默认收起字段”；

    2. **全局排序规则**：表格字段的全局排序要求，默认按金额降序、默认按时间降序等；

    3. **操作按钮控制：**单个数据操作：默认展示 3\-5 个常用按钮（如编辑、删除、审核），超出部分自动折叠，避免平铺占用空间；

    - **批量数据操作**：支持合并、打印、导出等需求，需提供复选框功能，允许用户选择部分数据导出（而非默认导出全部）；

4. 简单表单页面设计规则

    1. 字段数量：信息较少，通常不超过 10 个字段；

    2. 输入控件：使用多样化控件引导输入，如文本框、日期选择器、枚举下拉框、开关按钮等；

    3. 页面滚动：若输入信息一屏无法完整显示，需支持多屏滚动；

    4. 操作栏固定：关键信息（如商品名称、编码）需固定显示，便于用户录入助记码时快速定位；

5. 表格 \+ 表单混合页面设计规则

    1. 表单部分：使用文本框、日期选择器、开关等控件引导输入，支持文本、数值等类型信息录入；

    2. 表格部分：字段数量较多（通常超过 6 个），需展示数据汇总合计信息；

    3. 额外需求：需支持数据的导入、导出、打印功能，满足业务处理全流程需求；

6. 卡片类页面设计规则

    1. 信息范围：用于展示单个对象信息，字段较少（通常 6\-8 个以内）；

    2. 数据量控制：同一页面下的数据量可控，通过卡片化展示提升页面美观度；

    3. 附加功能：可能需支持图片上传需求，满足对象信息的可视化补充；

7. 报表页面设计规则

    1. 检索条件：支持多检索条件，满足精准筛选需求；

    2. 表格交互：表格数据需支持穿透查看、合并、页面跳转功能；

    3. 字段规则：字段前后排列顺序遵循业务要求，同时支持全局排序（如按金额 / 时间排序）；

    4. 数据操作：支持全部 / 部分数据的导出、打印，需提供数据小计与总计统计；

8. 图表页面设计规则

    1. 检索条件：支持多检索条件，筛选结果直接作用于图表展示；

    2. 展示形式：需呈现汇总类图表，同时支持 “图表” 与 “表格” 两种形式的切换查看，满足不同查看需求；

### 2\.2、常见数据类型

1. 规则文本

    1. 编码：编码核心需承载业务语义，通过固定规则区分商品属性，便于人工识别与管理。

        1. 规则示例：以 “大类 \- 中类 \- 小类” 三级分类为基础，用固定数字定义商品大类，如 1 代表原材料、2 代表物料、3 代表低值易耗、4 代表固定资产。

        2. 示例：编码 “10102030007” 可拆解为 “原材料（1）→ 第一个大类（01）→ 第二个中类（02）→ 第三个小类（03）→ 第七个商品（0007）”。

        3. 价值：熟悉业务的库管、生管、单据操作人员、运营拓展人员，可通过编码直接识别商品品类及对应货架位置，提升管理效率。

        4. 有名称对应就应该有编码的逻辑是不对的，中间数据只有名称无编码的情况是存在的。

    2. ID：ID 通常作为表或接口的唯一主键、外键，主要用于系统内部数据交互与关联。

        1. 生成方式：一般由系统自动生成，无需人工干预。

        2. 核心用途：用于系统内表关联、接口对接及数据映射工作，确保数据唯一性与准确性。

    3. 单号：单号分为凭证号与单据号两类，适用场景明确区分，均需保障唯一性。

        1. 凭证号：仅用于非单据对接的企业。例如 POS 会员营销使用 Menusifu 产品、财务软件使用金蝶、用友产品的对接模式，需通过凭证号实现不同系统间的数据关联（单据对接不使用此方式）。

        2. 单据号：默认按 “业务 \+ 年月日 \+ 流水号” 格式自动生成，核心作用是确保数据的唯一性与可追溯性，便于后续查询与核对。示例：CGSQ20250906000002，代表采购申请单的单据号，2025年9月6日创建的单据，为当天创建的第二笔单据。

2. 不规则文本（非结构化数据）

此类数据包括分类名称、商品名称、备注信息、地址信息、联系人信息等，核心特征如下：

1. 数据长度无统一标准，同一类数据内长度不一致；

2. 跨商户差异明显，即使是同一数据主体（如 “商品名称”），不同商户的录入长度也不统一；

3. 无需进行合计计算；

4. 需支持排序功能，默认按文本首字母升序排列；

3. 数值类型（量化数据）

    此类数据包括数量、单价、金额、品项数量、税率、小费等，核心特征如下：

    1. 数据长度无统一标准，不同类型数据（如 “数量” 与 “金额”）的长度不一致；

    2. 精度要求差异化，需根据数据类型单独定义（如金额保留 2 位小数、税率保留 1 位小数）；

    3. 跨商户存在差异，同一数据主体（如 “单价”）在不同商户间的长度可能不同；

    4. 需支持合计功能，主要针对数量、金额、品项数量三类核心数据；

    5. 需支持排序功能，主要针对数量、金额、品项数量三类核心数据；

4. 日期类型（时间维度数据）

此类数据包括业务发生日期、单据日期、创建日期、操作日期等，核心特征如下：

1. 数据长度统一，同一类型日期的格式长度无差异；

2. 跨商户无差异，同一数据主体（如 “单据日期”）在不同商户间的长度完全一致；

3. 无需进行合计计算；

4. 天然支持排序功能，可直接按时间先后顺序排列；

5. 细分 “日期型” 与 “日期 \+ 时间型”：前者仅展示年月日，后者需精确到时分秒（如操作时间、修改时间）；

## 三、产品设计规范

> 布局是页面构成的核心前提，更是后续开展交互设计与视觉设计的基础；设计者在选定布局方案前，需优先遵循以下两大原则，确保布局与用户需求、业务目标深度匹配：
> 
> 1. 锚定核心目标：明确用户在当前页面场景下，需完成的核心任务（如查询数据、提交表单、查看报表），以及支撑任务决策必须获取的关键信息（如商品价格、订单状态、统计数值），避免布局偏离用户核心诉求；
> 
> 2. 理清信息与操作优先级：基于用户任务，梳理决策信息与操作功能的优先级排序（如核心信息优先展示、高频操作优先触达），同时结合内容特点（如信息是表格类、卡片类还是表单类），选择最适配的布局形式（如左右分栏、上下层级、网格布局），确保信息传递高效、操作路径简洁；
> 
> 

### 3\.1、界面布局\-PC

**网站展示页（官网页）**

网站展示页是用户接触产品或品牌的 “第一印象入口”，核心目标是快速传递核心价值、引导用户下一步动作；设计需围绕 “清晰传递” 与 “高效引导” 展开：

- 聚焦信息核心：明确要传递的关键内容（如产品核心功能、品牌优势），文案需简短精炼，避免冗余信息干扰用户认知；

- 强化视觉辅助：搭配清晰、直观的产品图或场景图，直观呈现产品形态与用途，帮助用户快速理解并加深记忆；

- 突出关键入口：清晰放置用户登录、注册或核心转化按钮（如 “立即体验”“了解详情”），降低用户操作路径，提升转化效率；

**控制台页**：

控制台页是聚合多类型信息（数字、图形、文案）的 “数据中枢”，核心目标是让用户一目了然地掌握关键信息与整体情况；设计关键在于 “信息精简” 与 “重点突出”，需注意：

1. 按优先级排版：优先展示核心指标（如业务核心数据、异常提醒），次要信息（如辅助说明、历史数据）后置，避免注意力分散；

2. 数据可视化呈现：将复杂数据转化为折线图、柱状图、仪表盘等图表形式，帮助用户直观感知数据趋势、对比差异，降低理解成本；

3. 优化视觉体验：合理运用颜色（如用对比色突出异常数据）与栅格布局，规整信息模块，减轻用户视觉负担，提升浏览舒适度；

**表格页**：

表格页是 “并列式信息展示” 的核心载体，核心目标是让用户快速浏览基础信息、便捷执行操作；设计需围绕 “可阅读性” 与 “可操作性” 优化：

- 定义信息优先级：根据用户核心需求筛选展示内容，仅保留关键信息（如编码、名称、状态）与高频操作（如编辑、查看），剔除冗余项；

- 拆分复杂信息：若信息维度多，可将次要内容（如备注、历史记录）折叠隐藏或引导至详情页，通过 “递进式查看” 平衡信息完整性与页面简洁度；

**表单\+表格页**：

此类页面需同时满足 “信息录入” 与 “多维数据浏览” 需求，核心目标是让复杂信息更易读、操作更便捷；设计需兼顾 “布局清晰” 与 “视觉区分”：

1. 规整表格布局：采用清晰的行列结构，明确表头与数据对应关系，提升用户对信息的接收与理解速度；

2. 突出关键信息：通过字体加粗、颜色区分等视觉手段，强调核心数据（如金额、状态），帮助用户快速抓取重点；

3. 优化视觉区分：若表格列数多或单行列内容换行，可使用横向 / 纵向斑马纹（交替底色），清晰划分不同条目，降低视觉混淆；

**表单页：**

表单页是 “数据录入与任务执行” 的关键载体（如登录、注册、下单、评论），核心目标是引导用户高效完成操作；设计需围绕 “降低填写成本” 与 “提升完成率” 展开：

- 规划浏览路径：遵循用户习惯的阅读顺序（如从上到下、从左到右）排布表单项，避免视线来回跳跃，减少操作干扰；

- 精简填写内容：仅保留必要输入项（如剔除非必填的冗余字段），通过默认值、下拉选择等方式，减少用户手动输入量；

- 明确标签与反馈：标签命名需简洁易懂（避免模糊表述，如用 “手机号码” 而非 “联系电话”），同时将提交 / 完成按钮放在浏览路径终点（如页面底部居中），降低操作认知成本；

### 3\.3、文字

> 在界面设计中，文案是与用户对话的 “隐形桥梁”—— 不仅要靠精准清晰的表达帮用户理解操作，更要靠恰当的语气建立信任，其重要性需与视觉、交互设计同等重视；在撰写和使用界面文案时，需遵循以下核心原则：
> 
> 1. 站在用户视角表达：摒弃产品或技术侧的专业术语，用用户熟悉的语言描述功能或场景；例如不说 “触发异常”，而说 “操作遇到问题，请重试”，让用户快速感知问题并知道如何应对；
> 
> 2. 保持表述全局一致：同一概念、功能的称呼需贯穿全产品统一；比如 “提交订单” 不能在首页叫 “下单”、在确认页叫 “提交”；“删除” 也不能部分场景叫 “移除”，避免用户产生认知混乱；
> 
> 3. 关键信息优先凸显：将用户决策或操作必需的信息（如金额、有效期、错误提示）放在视觉焦点位置，可通过加粗、对比色等方式强化，让用户无需寻找就能快速获取核心内容；
> 
> 4. 确保专业精准完整：涉及数据、规则、流程的文案，需准确无误且信息完整；例如会员权益说明要写清 “享 8 折优惠（特例商品除外）”，避免模糊表述引发误解，同时体现产品专业性；
> 
> 5. 做到精简友好正面：用最短的文字传递核心意思，避免冗余修饰；语气上多使用 “请”“可以” 等友好词汇，少用 “禁止”“不得” 等强硬表述；即使是错误提示，也优先给出解决方案，如 “手机号格式不对，请填写 11 位数字”；
> 
> 

#### 3\.3\.1、字体

导航菜单字体的核心目标是清晰传递层级关系，帮助用户快速定位功能；设计需重点关注层级区分与交互状态：

- 层级差异化：通过字体大小、字重建立清晰层级；例如一级菜单用 16 号粗体（突出核心分类），二级菜单用 14 号常规体（细化功能），三级菜单用 12 号常规体（具体操作项），避免视觉混淆；

- 交互状态适配：默认状态用常规字体，鼠标悬浮或选中状态可通过 “加粗 \+ 主题色” 强化（如一级菜单选中后保持粗体并变色），让用户明确当前所处位置；

页签字体需强区分当前与备选状态，帮助用户快速识别当前页面；设计需聚焦状态对比：

- 当前页签：用高对比度样式突出，例如 14 号粗体 \+ 主题色（或底部加高亮下划线），成为视觉焦点，明确当前所处页面；

- 备选页签：用低干扰样式呈现，例如 14 号常规体 \+ 中性灰色，保证可识别性的同时，不抢夺当前页签的视觉注意力；

数据展示区字体需兼顾 “可读性” 与 “信息优先级”，让用户高效获取数据；设计需按信息类型差异化：

- 标题：用 16 号粗体，突出模块核心（如 “商品库存列表”），明确当前数据主题；

- 页面说明信息：用 12 号常规体 \+ 浅灰色，作为辅助提示（如 “注：仅展示近 30 天库存变动数据”），不干扰核心数据；

- 操作项：用 12\-14 号常规体 \+ 主题色（如 “编辑”“导出” 按钮），既醒目又不突兀，引导用户执行操作；

- 字段（表头 / 数据内容）：用 14 号常规体（表头可加粗），保证数据清晰易读，例如表格中 “商品名称”“库存数量” 等字段，字体统一且规整；

- 字段说明：用 12 号常规体 \+ 浅灰色，作为字段补充解释（如 “库存数量：包含在库与在途商品总和”），放在字段旁或 hover 时显示；

弹窗字体需聚焦核心信息与操作，避免用户在临时弹窗中分散注意力；设计需简化层级、突出重点：

- 弹窗标题：用 16 号粗体，直接传递弹窗目的（如 “确认删除商品？”“编辑商品信息”），让用户快速知晓弹窗作用；

- 提示文案：用 14 号常规体，清晰说明核心内容或风险（如 “删除后数据不可恢复，请确认”），语言精简且易懂；

- 操作项（按钮）：用 14 号常规体，核心操作（如 “确认”“提交”）可加粗 \+ 主题色，次要操作（如 “取消”）用常规体 \+ 中性色，引导用户优先执行关键操作；

#### 3\.3\.2、文案

> 输入框的默认文案（占位提示）需根据场景明确引导性，核心是帮用户快速理解输入要求，避免操作困惑，具体可分为以下三种形式：
> 
> 1. 提示填写格式：直接告知用户输入内容的规范，降低格式错误率；例如 “7\-13 位数字”“YYYY\-MM\-DD”“手机号格式”，让用户明确知道 “该填什么格式”；
> 
> 2. 传递业务重要提示：聚焦关键业务规则，且控制在 8 字以内，确保信息简洁不冗余；例如 “必填项”“最多 50 字”“仅支持中文”，让用户快速捕捉核心限制；
> 
> 3. 通用引导提示：无特殊格式或业务要求时，用基础文案引导操作，保持体验统一；例如 “请选择”（适配下拉选择框）、“请输入”（适配文本输入框），明确告知用户 “需要进行操作”；
> 
> 

1. 明确表述立足点：以用户为中心

    1. 核心聚焦 “用户能用产品做什么”，而非产品功能本身，立足点需围绕用户需求；

    2. 文案以用户为主体撰写，避免以产品或平台为核心的视角（如不说 “系统支持查询”，而说 “你可查询”）；

2. 精简语句：减少信息干扰

    1. 省略无用词汇与用户已知信息（如用户明确要填手机号时，不说 “你已知晓需填手机号，请输入”）；

    2. 绝大多数交互场景下，提供简短、易快速获取的内容，避免长句或复杂表述；

3. 用用户熟悉的语言：降低理解成本

    1. 使用简单、直接的常用词汇，避免间接、模糊表述，以及生僻、过度 “文雅” 的用词；

    2. 确保内容与操作指示易懂，不增加用户额外的认知负担（如不说 “进行账户校验”，而说 “验证账户”）；

4. 表述一致：保持全局统一

    1. 词汇统一：同一事物的描述需固定（如 “提交订单” 不拆分为 “下单”“确认订单”）；

    2. 格式统一：上下文的语法、语种、语序需一致（如不混用 “点击” 与 “click”，不颠倒 “姓名 \- 手机号” 与 “手机号 \- 姓名” 的顺序）；

    3. 关联统一：操作名称与目标页面标题需匹配（如 “查看订单” 按钮，对应页面标题应为 “订单查看” 而非 “我的订单列表”）；

5. 重要信息放在显著位置：优先传递关键内容

    1. 让用户第一眼看到核心信息，无需在段落或模块中寻找（如金额、有效期等关键数据置顶或加粗）；

    2. 涉及安全性的隐私信息，可设置为 “点击后可见”，平衡信息安全与查看便捷性；

6. 完整、直接阐述信息：明确目的与价值

    1. 引导操作时：需告知用户 “操作收益” 与 “必要性”，提升执行意愿（如不说 “完善资料”，而说 “完善资料可解锁会员权益”）；

    2. 报错提示时：需符合用户认知，用易懂方式说明问题（如不说 “参数异常”，而说 “手机号格式不对，请填 11 位数字”）；

7. 用词精准完整：避免歧义与错误

    1. 通用词汇：需规范使用，不写错别字，确保词语表达完整（如不说 “已阅”，而说 “已阅读”）；

    2. 专业用语：需精准且符合行业通用标准（如电商场景用 “退款” 而非 “返款”，财务场景用 “对账” 而非 “核账”）；

8. 语气：匹配用户群体，传递尊重

    1. 先匹配用户身份：对专业运维人员可使用行业术语，对小白用户需更通俗（如运维场景说 “日志排查”，小白场景说 “查看操作记录找问题”）；

    2. 再传递友好态度：多给支持与鼓励，忌命令或强迫（不说 “必须填写”，而说 “请填写”）；报错时不责怪用户（不说 “你填错了”，而说 “信息有误，请核对”）；忌绝对化表述（不说 “肯定能成功”，而说 “大概率可完成”）；

9. 大小写与基础格式

    1. 英文名词：产品全称首字母大写（如 “User Dashboard”），产品缩写全大写（如 “UI”“API”）；

    2. 专有名词：遵循其固定大小写规范（如 “Excel”“iOS”）；

    3. 全英文内容：标题、标签、菜单项等需符合英文句式首字母大写规则（如 “View Order” 而非 “view order”）；

    4. 统计数据：统一使用阿拉伯数字（如 “5 件”“30%” 而非 “五件”“百分之三十”）；

    5. 标点精简：省略不必要的标点（如标题后不加逗号、句号），助力用户高效扫视文本（含标签、输入框提示、悬停文本、表格内容等）；

10. 空格：保持视觉规整

    1. 段落句子中，链接与文字之间需加空格（如 “查看《规则》 详情”）；

    2. 数量、百分比等表述需统一（如统一用 “2 个” 而非 “两个”，统一用 “50%” 而非 “5 成”）；

11. 句号：明确禁用场景

以下场景不使用句号：

1. 输入框下的提示文本（如 “请输入手机号” 而非 “请输入手机号；”）；

2. 表格内的句子（如 “已发货” 而非 “已发货；”）；

3. 句末为文字链的内容（如 “查看更多详情” 而非 “查看更多详情；”）；

4. 按钮文案与标题（如 “提交” 而非 “提交；”，“订单列表” 而非 “订单列表；”）；

12. 感叹号：谨慎使用

仅在表达强烈情感或紧急提示时使用（如 “账号异常，请立即验证！”），日常引导或说明避免使用；

13. 连接号：禁用中文全角

统一使用半角连接号（如 “2024\-05\-01” 而非 “2024—05—01”）；

14. 省略号：统一半角格式

需使用半角 “…”，不使用中文全角 “……”（如 “加载中…” 而非 “加载中……”）；

15. 隐藏符号：保护隐私与简化展示

多用于替换隐私信息（如手机号显示 “138\*\*\*\*5678”）或冗余元素，平衡信息安全性与界面简洁性；

### 3\.4、导航区

> 从广义来说，导航的核心是为用户提供 “定位” 与 “引路” 的指引 —— 告知用户当前位置、可前往的方向及到达路径；设计者在使用或自定义导航结构时，需遵循以下原则，优化用户浏览体验：
> 
> 1. 强化定位感知：提供清晰的标识（如当前页签高亮、面包屑导航）与上下文线索，帮助用户明确 “自己在哪”，避免在页面中迷路；
> 
> 2. 降低认知成本：保持导航的样式（如颜色、图标）与交互行为（如点击反馈、展开逻辑）全局统一；或合理控制导航数量，减少冗余选项，让用户无需反复学习新的导航规则；
> 
> 3. 缩短操作路径：尽量减少页面间的跳转次数，例如将完成一个常见任务所需的跳转，从多次精简至 1\-2 次；既缩短用户的操作距离，也避免频繁切换页面带来的视角突兀感；
> 
> 

1. 导航菜单

    当前系统采用侧边栏导航样式，基于此样式，需从结构、文案、顺序三方面优化，具体规范如下：

    1. 菜单层级：支持扩展至 3 级菜单，满足多业务模块的层级划分需求，确保导航逻辑清晰；

    2. 文案限制：菜单文案字数不得超过 6 个汉字，避免文字过长导致显示拥挤，提升视觉简洁度；

    3. 顺序规则：菜单排列顺序需与业务推进流程一致，符合用户实际操作习惯，降低使用认知成本；

2. 标签页Tabs

    **使用前提**：考虑到国外用户使用习惯，需谨慎使用标签页，优先确保交互逻辑符合海外用户认知；

    **适用场景**

    1. 基础场景：将叶子菜单设置为标签页，实现菜单与内容的联动展示；

    2. 详情页场景：表格中信息量大的对象主体详情页，建议采用标签页形式呈现，具体包括：

        - 物品档案的新增、编辑页面

        - 各类单据的新增、编辑页面

        - 报表关联的明细表格页面

    **页签命名规则**

    新打开页签的命名需遵循 “核心信息 \+ 操作 / 标识” 原则，具体格式如下：

    1. 若为基础操作页面（如新增、编辑），直接以叶子菜单名称命名，示例：

        - 原页面：物品档案 \- 新增 → 页签名称：物品档案

        - 原页面：采购收货单 \- 新增 → 页签名称：采购收货单

    2. 若为特定单据编辑页面，需补充单据编号，示例：

        - 原页面：货单 \- 编辑（单据编号 CGSH20100） → 页签名称：采购收货单 CGSH20100

    **页签功能目的**

    1. 支持同时打开多个新增、编辑表单或单据页面，满足多任务并行操作需求；

    2. 允许用户同时编辑多个单据，提升业务处理效率；

    3. 当用户保存或关闭详情页签时，系统自动跳转至上一个页签，保障操作连贯性；

3. 步骤条 Steps

> 步骤条作为引导用户完成流程化任务的核心导航组件，需突出其 “流程预判、进度感知、完成度度量” 的核心价值，同时明确适用场景的必要性；以下是润色后的内容：
> 
> 步骤条是引导用户按既定流程完成任务的导航组件，核心价值在于三方面：一是帮助用户提前清晰认知任务的完整流程与各环节步骤，建立明确预期；二是实时提示用户当前所处的任务阶段，避免操作迷茫；三是直观呈现业务完成进度，让用户对任务整体完成度有量化感知；当任务逻辑复杂（如多环节关联操作）或存在严格先后顺序（如表单填写、审批流程）时，通过分布式布局展示流程步骤，能有效降低用户理解成本、提升操作连贯性，这种设计尤为必要；
> 
> 

**核心设计原则**：

1. 进度透明化清晰展示步骤总数（如 “3/5”）与用户当前所处位置，让用户对任务整体进度建立明确认知；

2. 命名精准化步骤名称需同时满足 “简洁性”（避免冗长描述）与 “唯一性”（各步骤名称不重复、无歧义），例如用 “信息填写” 而非 “填写你的个人信息”；

3. 状态可视化通过视觉差异（如颜色、图标、样式）明确区分 “未开始”“进行中”“已完成”“不可用” 等状态，避免用户混淆；

4. 流程适配性仅适用于 “线性流程”（步骤按固定顺序推进），严禁用于 “非线性 / 分支流程”（如存在多路径选择的场景），防止引导逻辑混乱；

**布局场景和适配规则**

1. 横向布局（首选）

    - 适用场景：PC 端或移动端横向空间充足时（如表单顶部、页面头部）；

    - 呈现形式：步骤从左到右依次排列，通过水平进度线连接，直观体现流程的连贯性；

2. 纵向布局（备选）

    - 适用场景：移动端竖屏显示或步骤名称较长时（如政务类流程 “材料准备、现场审核、结果公示”）；

    - 呈现形式：步骤从上到下垂直排列，通过垂直进度线连接，适配窄屏空间；

3. 折叠限制

    - 原则上禁用 “折叠步骤”（如 “1/3 → 展开更多”），避免增加用户操作成本；

    - 例外情况：仅当步骤数超过 5 步且处于移动端场景时，可谨慎使用折叠，但需确保展开 / 折叠操作便捷（如点击即可展开全部步骤）；

**交互与视觉规范**

1. 状态实时更新，当前步骤操作完成后，需立即同步更新步骤条状态（如从 “进行中” 变为 “已完成”），确保进度反馈及时；

2. 操作主动可控，必须由用户主动点击 “下一步” 按钮触发流程推进，严禁系统自动跳转或跳过某步骤，保障用户操作主权；

3. 风格一致性，步骤条的图片、图标、色彩需与产品整体设计风格统一，避免视觉突兀（如主色调、图标样式需匹配品牌规范）；

4. 视觉轻量化，避免过度装饰（如复杂动画、闪烁特效、冗余元素），防止分散用户注意力，确保用户能快速聚焦于进度判断与操作本身；

4. 分页器

> 当信息条目数量较多时，建议提供 “自定义每页显示行数” 的功能；该功能可提升信息检索的效率与灵活性，尤其适合与表格、卡片等信息承载组件搭配使用，帮助用户根据自身查看习惯快速定位所需内容；
> 
> 

分页器的场景化核心作用

1. **支撑部分数据的精准导出与打印**

用户执行导出或打印操作时，通常无需处理全量数据，仅需针对特定范围的数据开展操作；而目标数据可能存在跨页分布的情况，此时分页器可通过灵活控制每页数据量，搭配复选功能帮助用户批量选中所需数据，高效完成导出或打印流程，避免冗余数据对操作的干扰；需注意：当前设计若移除 “调整每页展示数据量” 的功能，可能会直接影响该场景下的操作效率，增加用户筛选、定位目标数据的成本；

2. **优化数据加载，保障系统性能**

当用户批量查看或操作数据时，常面临数据量庞大的场景；分页功能可通过 “按需加载” 的特性，仅加载当前页所需数据，而非一次性加载全部数据 —— 这一设计能有效避免系统性能资源被过度占用，减少页面加载延迟，保障用户操作的流畅性，尤其适用于数据量达数千条甚至上万条的场景；

3. **降低数据查看负荷，提升用户体验**

若全量数据不分页展示，页面易出现 “滚动条无限下拉” 的问题：用户需反复滑动页面才能定位目标信息，不仅增加操作成本，还可能因信息过载导致注意力分散；分页功能通过 “数据分段” 的方式，将庞大的数据集拆解为轻量化的页面单元，让用户能聚焦于当前页信息，快速定位所需内容，显著优化查看体验；

4. **适配多终端，实现差异化展示**

不同终端（PC 端、移动端、平板）的屏幕尺寸与交互方式差异显著：PC 端屏幕宽度充足，可承载更多数据；移动端竖屏空间有限，过多数据易导致页面拥挤；分页功能可通过 “灵活调整每页数据条数” 的特性，适配不同终端的显示需求 —— 例如 PC 端默认每页展示 20 条数据，移动端默认展示 10 条数据，确保各终端下数据展示的合理性与交互的便捷性；

5. 滚动条

    > 横向滚动条：
    > 
    > - 显示规则：采用显性显示模式，确保用户能直观感知横向可滚动区域及数据范围，避免因滚动条隐藏导致用户忽略横向延伸的内容（如表格多列数据、宽幅卡片）；
    > 
    > - 定位要求：固定于滚动区域的底部边缘，与区域边界对齐，保持位置稳定 —— 无论用户纵向滚动页面至何处，横向滚动条始终处于横向可操作区域的底部，确保交互位置可预期；
    > 
    > 纵向滚动条：
    > 
    > - 显示规则：同样采用显性显示模式，清晰传递纵向数据的长度与当前滚动位置，避免用户因无法感知纵向范围而重复无效滑动；
    > 
    > - 定位要求：固定于滚动区域的右侧边缘，与区域边界对齐，保持位置恒定 —— 即使页面存在横向滚动，纵向滚动条也始终处于纵向可操作区域的右侧，符合用户 “右侧滑动控制上下” 的操作习惯；
    > 
    > 

    1. 适配纵向长内容，控制页面篇幅适配纵向延伸的长内容（如长文档、多条目列表），通过滚动交互避免页面无限拉长，防止用户因频繁大幅滑动影响阅读与操作效率；

    2. 保持横向空间稳定，契合阅读习惯固定横向显示范围，避免横向内容随意拉伸页面，始终保持横向空间的稳定性，符合用户 “左右视野固定、上下滚动浏览” 的常规阅读习惯；

    3. 支持精准定位与进度感知借助滚动条的位置反馈，用户可直观判断当前在整体内容中的浏览进度，同时能通过拖动滚动条快速定位至目标区域，提升操作精准度；

    4. 适配横向宽内容，保障显示完整针对横向延伸的宽内容（如多列表格、宽幅图表），通过横向滚动功能避免内容被截断或挤压变形，确保信息完整呈现，不丢失关键数据；

    5. 保障特定内容完整性，规避功能失效对于依赖固定宽高比的内容（如数据表格、交互组件），滚动条可维持其原有布局结构，避免因内容压缩导致组件功能异常（如按钮不可点击、表格单元格错位）；

    6. 平衡多终端适配，降低响应式复杂度通过滚动条的标准化交互，无需为不同终端（PC 端、移动端）过度调整内容布局，减少响应式设计的开发与维护成本，同时保障各终端的一致体验；

### 3\.5、功能显示区

1. **页签区域规范**

不想写这，国外产品少有用页签的

2. **筛选条件区域规范**

    1. 查询层级区分明确默认查询与高级查询的边界，默认展示基础查询条件，高级查询条件需设置清晰的 “展开 / 折叠” 触发规则（如点击 “高级查询” 按钮展开），避免初始界面信息过载；

    2. 条件布局规则每行承载 2\-4 个筛选条件，确保界面紧凑且不拥挤；所有筛选条件的标题统一右对齐，提升视觉一致性，方便用户快速关联条件与输入项；

    4. 查询条件记忆支持跨页签跳转时保留查询条件（如从 “数据列表” 页签跳转至 “统计分析” 页签后返回，原筛选条件不重置），减少用户重复操作；

    5. 控件交互规则

        - 日期控件：支持日期范围选择（如 “起始日期 \- 结束日期”），默认展示最近 30 天等常用范围；

        - 文本框：支持模糊查询与精确匹配切换（如勾选 “精确匹配”）；

        - 复选框：勾选 3 个及以下选项时，直接显示选项内容；勾选超过 3 个时，仅展示 “已选 X 项” 的数量提示，避免占用过多空间；

3. **表格显示区域规范**

    **字段对齐与基础布局**

    1. 对齐方式：文本类字段（如名称、描述）左对齐，数值类（如金额、数量）、符号类（如编码、单号）字段左对齐，提升阅读效率；

    2. 宽度控制：表格默认宽度适配页面，支持拖拽调整列宽；同时提供 “自定义列宽” 设置入口，满足用户个性化需求；

    **信息展示规则**

    1. 内容长度处理：有信息时限制显示长度（如最多显示 20 个字符），超出部分用 “…” 省略，鼠标悬浮时弹窗展示完整内容；

    2. 空值展示：无信息的单元格直接显示为空，不使用 “\-”“/” 等占位符，避免导出数据时产生无效值，确保数据准确性；

    **交互与视觉反馈**

    1. 滚动条设置：横向滚动条固定在表格底部，纵向滚动条固定在表格右侧，均采用显性显示，让用户清晰感知可滚动范围；

    2. 高亮效果：鼠标悬浮行或选中行时，通过不同颜色背景区分（如悬浮行浅灰、选中行深灰），避免与表格内容颜色冲突；

    3. 排序功能：

        1. 支持全局排序（非仅当前页排序），切换页签或翻页后保留排序规则；

        2. 支持升序、降序及多字段级联排序，所有可排序字段点击表头即可触发；

        3. 可排序字段范围：数值类（品项数、数量、金额）、日期时间类（业务日期、操作时间）、规则文本类（编码、单号、凭证号）；不规则文本类（如备注、描述）根据业务需求判断是否支持排序；

    **数据合计规则**

    1. 本页合计：数值类字段需显示本页合计（如表格底部展示 “本页合计：数量 100，金额 5000”），适用于列表页、表单页、单据等场景；

    2. 全局合计：筛选结果的全局合计数，显示在检索结果栏（如 “共找到 200 条数据，合计金额 10000”），具体合计字段根据业务场景确定；

    **列管理与数据导出**

    1. 字段列选择

        1. 各业务模块默认展示字段（含顺序、显隐状态）需结合业务逻辑预设；

        2. 用户自定义列显隐、排序后，随账号保存，再次进入该模块自动加载历史设置；

    2. 导出功能：支持 “导出当前页数据”“导出全部筛选数据”，导出字段与用户当前列选择保持一致（仅导出显示中的字段）；

    3. 打印功能：打印内容由系统预设的打印配置决定，与用户当前列选择无关，确保打印文档的标准化；

    分页：

    > 仅当加载或渲染全量数据会明显耗时（如数据量超过XX 条）时使用分页；多应用于表格、列表等数据密集型场景；若表格数据不足一屏（如10 条），则不显示分页控件；

    > 

    1. 每页条数设置：支持用户选择每页显示条数（默认提供 10、20、50、100 等选项），用户选择后随账号保存，下次进入自动应用；

    2. 状态记忆：翻页后或跨页签跳转返回时，保留之前的页码与每页条数设置，无需重新操作；

    3. 分页场景限制：列表页、报表数据页需分页；详情页、编辑页、表单操作页不分页，避免打断用户操作流程；



### 3\.6、按钮

**新增：添加单条或多条记录**

1. 记录排序规则：列表页新增的记录需排在首页首行，确保用户快速定位；表单操作页新增的记录则排在末尾，符合表单数据的自然流转逻辑；

2. 提交失败处理：提交失败后必须完整保留用户已输入的内容，避免重复填写，方便用户修改后重新提交；

3. 数据校验要求：提交时需对主要标识字段（如编码、单号）进行校验，包括重复值校验（避免与已有数据冲突）和空值校验（防止关键信息缺失）；

**编辑：修改单条或多条记录**

1. 批量编辑校验：若界面包含复选框，勾选多条记录编辑时，点击 “保存” 需触发全局校验（而非单条校验），确保所有编辑记录均符合规则；

2. 编辑后定位：编辑完成后需自动返回原记录所在位置，并实时刷新显示最新内容，避免用户重新查找；

3. 提交失败处理：提交失败后保留用户已编辑的内容，支持用户修正错误后再次提交，减少操作成本；

4. 查询条件适配：在特定查询条件下编辑记录，返回列表后若该记录不再满足原查询条件，则不显示该记录，确保列表数据与查询条件一致；

5. 数据校验要求：需对主要标识字段进行校验，涵盖重复值、空值、空格（避免无效空格导致的数据异常）三类场景；

**删除：移除单条或多条记录**

1. 敏感操作提示：删除属于高风险操作，触发时必须弹出确认提示（如 “确认删除选中的 1 条记录？删除后不可恢复”），防止误操作；

2. 删除后显示：删除成功后，被删除的记录需立即从列表中隐藏，确保界面数据与实际状态一致；

3. 删除后定位：删除完成后返回原记录所在页面（而非初始页面），维持用户操作连贯性；

4. 关联记录判断：若被删除记录与其他记录存在业务关联（如订单关联商品），需根据具体业务规则判断是否允许删除（如关联未解除时禁止删除）；

**查询：按条件筛选数据**

1. 查询后定位：每次执行查询后，列表自动定位到首页，方便用户从起始位置浏览结果；

2. 查询条件记忆：查询后保留当前所有筛选条件（如日期范围、关键词），用户再次查询时无需重新设置；

3. 重置功能搭配：当查询条件数量较多（如超过 5 个）时，需同步提供 “重置” 按钮，支持一键清空所有条件，恢复默认状态；

4. 无结果提示：未查询到匹配记录时，需显示明确提示（如 “未找到相关记录，请调整查询条件后重试”），避免用户误解为系统异常；

5. 查询方式支持：除用户明确要求关闭外，需默认提供模糊查询（关键词匹配）、精确查询（完全一致匹配）、单选 / 多选查询（下拉框或复选框筛选），满足不同查找需求；

**重置：恢复当前变更（不返回页面）**

1. 重置一致性要求：重置后页面状态需与初始进入时完全一致，包括查询条件、列显隐、排序规则等，无任何残留变更；

2. 防重复点击控制：需限制重复点击频率，可设置 “x 秒内最多点击 y 次” 或固定点击间隔（如 1 秒内仅允许 1 次），避免系统资源浪费；

**取消：终止当前操作**

1. 二次确认场景：在数据量较多的页面（如千条级列表）中，若用户已修改数据，点击 “取消” 需触发二次确认（如 “确认取消？已修改内容将不保存”），防止误删操作；

2. 取消后定位：取消操作后返回原记录所在位置，不跳转页面，维持当前浏览上下文；

3. 按钮统一性：若界面存在 “×” 关闭按钮（如弹窗右上角），需全局统一 “是否额外提供取消按钮” 的规则（如弹窗仅保留 “×” 或同时保留 “取消” 按钮），避免交互混乱；

**保存：固化当前变更**

1. 长耗时提示：若保存操作预计耗时较长（如批量保存百条数据），需显示进度提示（如 “保存中…30%”），告知用户操作进度，避免用户重复触发；

2. 防重复保存控制：需限制重复点击 “保存”，可设置 “x 秒内最多点击 y 次” 或点击后禁用按钮至操作完成，防止生成重复数据；

**返回：跳转至前一页面**

1. 返回路径规则：从页面通过按钮 / 链接进入子页面（如列表→详情），点击 “返回” 需精准回到触发跳转的原页面，而非随机页面；

2. 与取消的区别：“取消” 仅终止当前操作，无页面跳转功能（如关闭弹窗、停留当前页）；“返回” 则明确触发页面层级跳转，二者不可混淆；

**翻页：切换数据页面**

1. 带条件翻页：若当前列表存在筛选条件，翻页时需同步执行查询功能，确保所有页面数据均符合当前条件，避免出现条件外数据；

2. 子页面初始定位：翻页后进入子页面（如某页第 5 条记录的详情），子页面需从首项内容开始显示（而非承接翻页位置），符合用户浏览习惯；

3. 复选状态记忆：若列表支持单页复选功能，翻页后需保留已勾选记录的选中状态（如第 1 页勾选 2 条，切换至第 2 页后返回，勾选状态不变），支持跨页批量操作；

**全选：批量选中记录**

1. 全选范围：勾选 “全选” 按钮时，仅选中当前页所有记录（而非全量数据），避免用户误选非目标页面数据；

2. 全选状态联动：若取消当前页任意一条已选中记录的勾选，“全选” 按钮需自动取消勾选，确保状态同步；

3. 跨页状态保留：翻页后需保留之前页面的已勾选记录及 “全选” 按钮状态（如第 1 页全选，切换至第 2 页后返回，第 1 页仍保持全选），支持跨页批量操作；

### 3\.7、排序

> 1. 基础数据类型：数值类（如金额、数量）、日期类（如业务日期、单据日期）、时间类（如操作时间、提交时间）字段，必须支持全局排序，确保数据按数值大小、时间先后等逻辑跨页有序展示；
> 
> 2. 规则文本类型：编码（如物品编码、用户编码）、单号（如订单号、采购单号）等具有固定格式的文本字段，需支持全局排序，方便用户按标识规律快速定位数据；
> 
> 3. 其他文本类型：备注、描述、名称等非规则文本字段，可根据具体业务需求判断是否支持全局排序（如 “商品名称” 需按字母 / 拼音排序则支持，无排序需求则可不支持），避免冗余功能；
> 
> 

**表格全局排序设计方案**

**核心排序规则**

1. 排序范围：基于检索结果进行全局排序，确保跨页数据遵循统一排序逻辑，避免仅当前页有序的情况；

2. 排序方式：支持升序与降序两种模式（如数值从大到小、日期从新到旧），满足不同数据查看需求；

3. 交互触发：采用 “点击字段表头” 直接触发排序，无需依赖单独的排序小三角图标，简化操作路径，提升交互直观性；

**字段排序支持范围**

1. 基础数据类型（必支持）数值类、日期类、时间类字段均需支持排序，覆盖核心业务数据场景：

    - 日期 / 时间类：操作日期、单据日期、最近修改时间等；

    - 数值类：品项数、数量、金额等；

2. 规则文本类型（需支持）具有固定格式或编码规律的文本字段需支持排序，方便按标识快速定位：

    - 示例：物品编码、订单号、采购单号等；

3. 不规则文本类型（灵活适配）备注、描述、商品名称等非标准化文本字段，规范不强制要求排序，可根据具体业务需求（如是否需按字母 / 拼音排序）决定是否支持；

### 3\.8、顺序

> 1. 字段排序核心原则表格字段需按业务重要性或语义逻辑从左到右排列（如 “基础信息→业务数据→操作项”），确保用户优先查看核心内容，符合信息获取习惯；
> 
> 2. 主键字段特殊规则
> 
> - 主键字段（如物品编码、订单 ID）需固定排在最左侧第一位，方便用户快速识别数据唯一性标识；
> 
> - 支持主键列锁定功能，系统需根据用户当前屏幕宽度自动判断是否默认锁定（如窄屏时自动锁定，宽屏时保留手动锁定选项），避免横向滚动时丢失关键标识；
> 
> 3. 通用字段必排要求所有支持操作的表格数据，均需在字段序列中包含 “最近修改用户” 与 “最近修改时间”，且建议排在业务字段之后、操作按钮之前，便于用户追溯数据更新记录；
> 
> 

**主数据列表**

主数据列表需优先展示数据唯一性标识与核心基础信息，默认字段排序如下：

1. 序号

2. 编码（如物品编码、客户编码）

3. ID（数据唯一标识）

4. 名称（如物品名称、客户名称）

**单据列表**

单据列表需突出业务时间、单据标识及关键业务数据，默认字段包含（按优先级排序）：

1. 序号

2. 业务日期（如订单日期、入库日期）

3. 单号（如订单号、采购单号）

4. 角标（如状态标识：“已审核”“待付款”）

5. 品项数（单据关联的商品 / 物料数量）

6. 金额（单据总金额、应付金额等核心数值）

**单据详情页（新增 / 修改 / 查看）**

单据详情需展示明细维度的完整信息，覆盖 “标识 \- 属性 \- 数量” 核心逻辑，默认字段包含（按优先级排序）：

1. 序号

2. 编码（如商品编码、原材料编码）

3. 商品名称（或原材料名称）

4. 规格（如尺寸、型号、材质）

5. 商品类别（或原材料类别）

6. 数量

7. 原材料（针对需关联上游物料的场景，如生产单据）

**报表类列表**

报表类表格因业务场景差异较大（如统计报表、明细报表），字段配置需单独梳理，需结合报表核心目标（如数据汇总、趋势分析）确定字段优先级与展示范围，避免通用规则限制业务灵活性；

### 3\.9、查询

> 1. 检索条件布局规则每行承载 2\-4 个检索条件项，且检索条件总展示行数不可超过 2 行，避免初始界面信息过载，保持简洁性；
> 
> 2. 基础交互要求
> 
>     1. 所有检索条件均需配置明确标题，确保用户清晰理解条件含义（如 “订单日期”“商品编码”）；
> 
>     2. 检索条件的标题统一右对齐，与左侧输入框 / 选择器精准对齐，提升视觉规整度；
> 
> 3. 高级查询触发逻辑当检索条件总数超过 2 行承载上限时，需隐藏超出部分，通过 “高级查询” 入口控制展开 / 收起，平衡信息完整性与界面简洁性；
> 
> 4. 查询轨迹交互规则
> 
>     1. 触发高级查询后，需在结果区顶部显示查询轨迹（即已选条件汇总，如 “订单日期：2025\-10\-01 至 2025\-10\-16 \+ 状态：已付款”）；
> 
>     2. 查询轨迹支持单个条件删除，点击某条件后的 “删除” 按钮（如 “×”），系统需根据剩余条件 \+ 用户当前排序方式，对查询结果进行全局刷新；
> 
> 5. 查询结果展示要求查询结果的全局合计数据（如总金额、总数量），需在表格表头下方单独区域显示，方便用户快速获取整体统计信息，无需滚动至表格底部查看；
> 
> 

1. 主键字段查询支持列表中可见的所有主键类字段（如商品名称、商品分类、商品类型），均需配置为查询条件，确保用户可通过核心标识快速定位数据；

2. 单据详情查询逻辑从单据详情页发起查询时，需将用户直观感知的元素设为查询条件（如单据关联的 “客户名称”“商品规格”，而非后台字段 “客户 ID”“商品编码”），降低操作理解成本；

3. 查询条件顺序原则查询条件的展示顺序需与表格字段顺序完全一致，保持前后操作的逻辑连贯性，避免用户记忆偏差；

4. 关联条件排序规则

    1. 存在业务关联的条件字段需集中排列（如 “商品名称” 与 “商品类型” 相邻展示），方便用户组合筛选；

    2. 筛选范围更广的条件字段需排在靠前位置（如 “商品类别” 排在 “商品名称” 之前），符合 “先大范围缩小、再精准定位” 的查询习惯；

### 3\.10、数值数据规范

> 1. 界面显示精度控制数据精度需设为系统参数，支持用户根据业务需求自主配置界面显示精度（如金额保留 1 位或 2 位小数）；界面展示时，所有数值需按配置精度进行四舍五入处理，确保显示数据的准确性与一致性；
> 
> 2. 数据库存储长度标准不同类型数据的数据库存储长度需按以下规则统一设定，避免存储冗余或精度丢失：
> 
>     1. 数量：存储 2 位小数
> 
>     2. 单价、金额：存储 6 位小数
> 
>     3. 税率、换算率：存储 2 位小数
> 
> 3. 数值位数补齐要求界面展示单价、数量、金额时，需根据用户配置的显示精度自动补齐小数位数（如精度设为 2 位时，“10” 需显示为 “10\.00”，“15\.5” 需显示为 “15\.50”），确保数值格式统一；
> 
> 

**数量精度**

1. 系统参数设置：数量精度支持 2\-6 位小数选择，界面默认显示为当前配置的 2 位精度；

2. 特殊界面适配：若部分特殊界面有单独精度要求（如生产单据需 4 位），则以页面标注的精度为准，优先满足场景需求；

3. 合计栏计算规则：合计栏数值需先按数据库中各行原始数据计算总和，再根据当前显示精度处理，避免分步舍入导致误差；

4. 显示格式要求：根据配置精度自动补齐小数位数；明细与合计栏均不使用千分符（如精度 2 位时，“123” 显示为 “123\.00”）；

**单价精度**

1. 系统参数设置：单价精度支持 2\-6 位小数选择，界面默认显示为当前配置的 2 位精度；

2. 全局生效规则：用户确定精度后，所有页面的单价展示均统一采用该精度，确保数据格式一致；

3. 显示格式要求：根据配置精度自动补齐小数位数；明细与合计栏均不使用千分符（如精度 3 位时，“45\.6” 显示为 “45\.600”）；

**金额精度**

1. 系统参数设置：金额精度支持 2\-6 位小数选择，界面默认显示为当前配置的 2 位精度；

2. 全局生效规则：用户确定精度后，所有页面的金额展示均统一采用该精度，避免格式混乱；

3. 合计栏计算规则：合计栏数值需先按数据库中各行原始数据计算总和，再根据当前显示精度处理，保证合计结果准确；

4. 显示格式要求：根据配置精度自动补齐小数位数；明细与合计栏中，超过千位的金额需使用美式千分符（如精度 2 位时，“123456\.7” 显示为 “123,456\.70”）；

**税率精度**

1. 精度固定规则：税率固定保留 2 位小数，展示时靠右对齐，无需用户手动配置；

2. 显示格式要求：无需按精度补齐位数（如 “6” 直接显示为 “6”，而非 “6\.00”）；需附带单位 “%”（如 “6%”“13%”）；

**换算率与百分比精度**

1. 精度固定规则：换算率与百分比均固定保留 2 位小数，展示时靠右对齐，无需用户手动配置；

2. 显示格式要求：无需按精度补齐位数（如 “1\.2” 直接显示为 “1\.2”，而非 “1\.20”）；

### 3\.11、反馈规范

> 为帮助用户明确当前操作目标、知晓下一步方向及预判操作结果，系统需在用户交互过程中提供精准反馈；设计反馈机制或自定义反馈内容时，需遵循以下规则：
> 
> 1. 反馈时效与必要性为用户操作的各个阶段（如输入中、提交后、加载完成）提供必要、积极且即时的反馈，避免用户因信息缺失产生困惑；
> 
> 2. 反馈精简原则避免过度反馈造成用户干扰；对于操作后效果直观可见、流程简单的行为（如文本框输入文字、单选按钮切换），可省略专门的反馈提示；
> 
> 3. 关键操作反馈要求用户操作涉及业务 “生效” 或 “失败” 的核心场景（如审核单据、删除数据、提交表单、终止流程），必须采用弹窗确认的阻断式反馈，强制用户确认后再执行，防止误操作；
> 
> 4. 反馈文案规范反馈文案需言之有物、清晰具体，禁止使用技术开发语言或模糊表述；
> 
>     1. 正确示例：请输入 7\-20 位数字
> 
>     2. 错误示例：输入不合法（未说明具体要求）
> 
> 

**警告提示（Alert）**

作为非阻碍式信息展示组件，不打断用户当前操作，分为两种展现形式：

1. 动态形式：短暂停留后自动消失，适用于临时告知类信息；

2. 静态形式：始终展示，需用户主动点击关闭；关闭按钮可根据业务需求决定显示或隐藏；

**通知提醒（Notification）**

用于系统主动推送重要全局性通知，默认在系统右上角显示，核心承载三类信息：

- 通知栏 Push

- 站内信

- 短信通知

**徽标数（Badge）**

聚焦聚合型消息提示，核心设计规则如下：

1. 展示位置：通常置于通知图标或用户头像的右上角；

2. 提示方式：针对重要性高、与用户关联度强的信息，采用 “数字精准提示” 或 “红点提示” 两种形式；

**气泡卡片（Popover）**

适用于目标元素需补充复杂信息或关联操作的场景，核心特点：

1. 功能定位：收纳对目标元素的进一步描述文字及相关操作按钮；

2. 与 Tooltip 区别：可承载更复杂的内容（如表单、列表），而非仅简单文本；

**文字提示（Tooltip）**

用于精准描述被指向对象，设计规则如下：

1. 适用对象：图标、图形、链接等无明确文字说明的元素；

2. 触发方式：鼠标悬停时自动展示简短说明文字；

**加载状态进度反馈**

针对操作耗时场景，确保用户感知流程进度：

1. 触发条件：当操作预计耗时超过 2 秒时，需即时展示加载进度说明，保持与用户的交互沟通；

2. 适用场景：优先用于用户无需长时间等待的加载过程，避免过度使用；

**录入反馈**

聚焦用户输入环节的即时校验，辅助用户修正内容：

1. 反馈方式：通过预设校验规则（如格式、长度），实时提示填写问题；

2. 展示位置：反馈文字需紧邻对应录入区块；此类反馈多为错误说明，需用户更新内容后才自动消失；

**气泡确认框（Popconfirm）**

用于目标元素操作需二次确认的场景：

1. 展示位置：在目标元素附近弹出，避免遮挡核心操作区；

2. 交互逻辑：需用户手动点击 “确认” 或 “取消”，完成决策后弹窗关闭；

**顶部全局提示反馈（Message）**

由用户操作触发的轻量反馈组件：

1. 展示位置：页面顶部居中，浮层形式呈现；

2. 消失规则：无需用户手动关闭，自动消失；

**对话框反馈**

用于承载重要操作结果或关键信息的强反馈组件：

1. 展示位置：页面中心，需用户主动交互后才关闭；点击 “知道了”“OK”“确认” 等按钮即可关闭弹窗；

2. 使用原则：仅在反馈重要信息时使用，避免不必要的弹窗；操作失败场景除外，不展示冗余提醒弹窗；

### 3\.12、导出规范

**导出文件命名规则**

根据导出内容类型，统一采用 “核心标识 \- 日期 \+ 流水号” 的命名格式，确保文件可快速识别与追溯：

1. 单个单据导出：文件名为 “导出页面标题 \- 单号 / 日期 \+ 流水号”，示例：标准商品 \- 20251015000001；

2. 多单据导出：若多单据合并导出为 1 个文件（含多个 sheet），命名规则同单个单据，示例：标准商品 \- 20251015000001；

3. 报表导出：文件名为 “报表名称 \- 导出日期 \+ 流水号”，示例：XX 汇总表 \- 20251101000001；

4. 主数据导出：文件名为 “主数据档案名称 \- 导出日期 \+ 流水号”，示例：成本卡档案 \- 20251101000001；

**导出文件格式要求**

1. 表头样式规范

    1. 字体设置：统一使用黑体、四号、加粗，保证表头清晰醒目；

    2. 显示方式：采用平铺显示，避免表头合并导致的信息混乱；

2. 表头内容规则

    1. 单据类导出：表头需完整展示单据表头信息（如订单编号、业务日期、供应商等）；

    2. 报表类导出：表头需包含报表筛选条件（如时间范围、区域筛选等），明确数据统计维度；

3. 导出数据规范

    1. 字段范围：导出数据的字段与页面展示字段完全一致，不额外增减；

    2. 格式统一：导出数据的格式（如数值精度、日期格式）与页面展示保持一致，确保数据连贯性；

    3. 合计展示：导出文件中是否包含合计栏，与页面是否显示合计保持一致，统一数据统计逻辑；

### 3\.13、打印规范

> 打印输出需遵循两大核心规则，确保信息展示适配场景、重点突出：
> 
> 1. 适配性原则：打印内容需严格根据当前选定的纸张规格（如 A4、A5、三联单）与预设的打印模板进行适配，避免内容溢出或排版错乱；
> 
> 2. 优先级原则：在有限的纸张容量内，优先显示最重要的核心信息（如单据编号、金额、关键审批节点），次要信息（如备注、附加说明）可按需简化或隐藏，确保核心内容清晰可见；
> 
> 

**打印样式要求**

表头样式：统一采用黑体、四号字体、加粗格式，确保表头醒目，提升内容辨识度；

**必选打印项规则**

以下信息为不可忽略的核心打印项，需在所有打印文档中完整呈现：

1. 单号（如订单号、单据号）

2. 单据状态（如已审核、待确认）

3. 打印人（显示操作人姓名）

4. 打印时间（格式为 yyyy/mm/dd hh:mm:ss，精确到秒）

5. 打印次数（格式为 第 x 次打印，避免重复打印导致的混淆）

**打印数据规范**

1. 数据完整性：打印的核心业务数据不可省略，若内容长度超出纸张宽度，可通过折行展示，确保信息完整；

2. 格式统一性：打印数据的格式（如数值精度、日期样式）需与系统页面展示完全一致；

3. 对齐一致性：数据的对齐方式（如数值右对齐、文本左对齐）需与系统页面保持统一，维持排版规整；

4. 合计同步性：打印文档中是否包含合计栏，需与系统页面是否显示合计保持一致，确保统计逻辑统一；

### 3\.14、icon使用规范

> 1. 图标设计基础：所有图标需采用语义化矢量图形，确保缩放后清晰度不变，且图形含义与对应功能强关联，降低用户理解成本；
> 
> 2. PC 端图标使用原则：PC 端业务流程中的主要操作，不建议使用图标单独承载；
> 
>     1. 核心原因 1：考虑到部分操作用户软件操作能力有限，纯图标易造成识别混淆；
> 
>     2. 核心原因 2：业务本身存在认知门槛，需用户学习理解，纯图标会进一步增加操作难度；
> 
> 3. 图标使用边界：具体哪些场景、操作可使用图标，需以UED（用户体验设计）团队的最终规范为准，确保设计一致性与用户体验平衡；
> 
> 

**通用性图标（建议使用）**

互联网环境中已形成普遍认知的图标，可直接采用以提升交互效率：

- 基础功能类：电话、提示、关闭、删除

- 业务元素类：坐标、账号、积分

**专有标识图标（规范使用）**

具有明确专属指向性的标识，需严格使用官方标准图标：

- 支付渠道类：微信、支付宝

- 货币 / 服务类：人民币、云（云服务）

**App 端适配图标（精简使用）**

因移动端显示区域有限，需优先保留高频操作图标，具体包括：

- 核心操作类：新增、修改、删除

- 通讯相关类：提醒、联系人、联系电话

所有图标使用需确保视觉一致性，优先采用系统统一图标库；若需新增特殊图标，需经 UED 团队确认，保证用户认知连贯性；

### 3\.15、快捷键规范

**Enter 键功能**

根据不同页面场景，Enter 键功能定义如下：

1. 登录页：触发 “登录确定” 操作，提交账号密码信息；

2. 弹窗：触发 “确定” 或 “保存” 操作，提交弹窗内表单或确认操作；

3. 详情页：

    - 表单区域：跳转至下一个可编辑单元格，自动跳过不可编辑单元格，顺序为从左到右；

    - 单据明细区域：当前行编辑完毕后，按下 Enter 键默认自动新增一行数据；

    - 商品 / 原材料输入：输入内容后，按下 Enter 键完成定位确认；

**Tab 键功能**

Tab 键功能按 “单据明细页” 和 “单据列表页” 区分：

1. 单据明细页：

    - 表单区域：跳转至下一个可编辑单元格，自动跳过不可编辑单元格，顺序为从左到右；

    - 初始化场景：页面加载完成后，按下 Tab 键可获取初始操作焦点；

2. 单据列表页：

    - 行切换：从当前光标定位行切换至下一行，顺序为从上到下；若当前为最后一行，按下后切换至最上方一行；

    - 按钮切换：从第一个功能按钮依次切换至最后一个按钮，切换至最后一个后，按下 Tab 键循环回到第一个按钮；

**方向键（上下键 / 左右键）功能**

1. 上下键

- 单元格切换：在当前定位单元格的同字段列，切换至下一行或上一行的对应单元格；

- 查找定位：商品 / 原材料模糊查询时，按下上下键可定位到查询结果中的目标选项；

2. 左右键

- 单元格切换：在当前行内，切换至左侧或右侧的可编辑单元格；

- 文本框操作：当光标位于文本框内时，按下左键可在文本框内的字符间向左移动光标；

**ESC 键功能**

ESC 键统一用于 “关闭” 类操作，具体场景包括：

- 关闭各类弹窗（如确认弹窗、表单弹窗）；

- 关闭系统提示（如警告提示、操作结果提示）；

- 关闭气泡悬浮（如气泡卡片、文字提示）；

### 3\.16、光标焦点规范

**简单说明，暂时用不上**

**基础输入框**

1. 新增空白状态：激活输入框时，提示文字自动消失，光标定位在第一个字符输入位，等待用户输入；

2. 修改状态（含内容）：激活输入框时，自动全选已有文本内容，光标置于选中内容的末尾，便于用户直接替换或追加内容；

## 四、全局业务规范梳理

> 全局统一命名规范
> 
> 为避免差异化导致的系统混乱，以下命名需保持全局一致性，修改后将影响所有关联模块：
> 
> 1. 基础命名类：包括按钮名称（如 “提交”“取消”）、菜单名称（如 “商品管理”“订单查询”）、操作按钮名称（如 “新增单据”“批量删除”）及字段名称（如 “商品编号”“订单金额”）；
> 
> 2. 核心原则：所有命名需遵循 “一词一义”，禁止同一功能 / 字段在不同模块使用不同名称，确保用户认知统一；
> 
> 字段展示规则梳理
> 
> 需明确字段在页面中的展示逻辑，确保一致性与易用性：
> 
> 1. 展示顺序：统一规定各模块字段的默认展示顺序（如按 “基础信息→业务信息→辅助信息” 排序），避免同一字段在不同页面位置混乱；
> 
> 2. 显示控制：明确字段的默认展示规则（如哪些字段默认显示、哪些需手动勾选）及收起规则（如是否支持折叠隐藏、折叠触发条件）；
> 
> 数据存储上限设置
> 
> 针对核心业务数据，需预设明确的存储数量上限，避免系统性能问题：
> 
> 1. 商品类数据：包括标准商品、套餐、加料的存储上限；
> 
> 2. 基础物料类数据：主要指原材料的存储上限；
> 
> 3. 设置原则：上限值需结合业务规模与系统性能评估确定，设置后需在后台配置界面明确标注，便于管理员查看与调整；
>

[删除逻辑说明](https://b1fo0wvbn3.sg.larksuite.com/wiki/M90XwGZzPi3WIxkj7ial8W20gSf)

> 为避免误删数据导致业务流程中断，系统对商品相关信息的删除操作设定以下权限规则，明确可删与不可删场景：
> 
> 允许删除的信息类型
> 
> 1. 分组关联类信息：规格、加料、做法、口味；
> 
>     - 删除条件：此类信息仅被各自的组引用，且该组未关联到任何菜品时，允许删除；
> 
> 2. 辅助描述类信息：图片、描述标签、角标、统计标签；
> 
>     - 规则：无需关联校验，直接允许删除，满足灵活调整需求；
> 
> 禁止删除的信息类型
> 
> 1. 被菜单引用的商品相关信息
> 
>     - 禁止原因：部分业务场景中，关联菜品与管理菜单的操作由不同人员负责，删除会导致菜单数据缺失，影响前端展示与订单生成；
> 
> 2. 被商品本身引用的商品相关信息
> 
>     - 禁止原因：此类信息为商品的核心组成部分（如基础属性、关联配置），删除会破坏商品数据完整性，导致商品无法正常使用；
> 
> 删除统一逻辑删除，而非物理删除

### 4\.6、列表字段对齐规范

为保证页面整洁统一，所有数据展示需遵循固定对齐规则：

1. 表格标题对齐原则表格标题的对齐方式需与对应列的数据对齐方式完全一致，避免标题与数据错位，确保界面视觉规整统一；

2. 数值类型字段

    1. 对齐方式：右对齐

    2. 适用场景：涵盖商品数、数量、金额、税率等所有数值类数据，通过位数对齐让数值大小对比更直观（如 “120”“1,200” 右对齐后，整数位与小数位分别对齐）；

3. 固定长度类型字段

    1. 对齐方式：左对齐

    2. 适用场景：包括日期（如 “2025\-10\-16”）、日期 \+ 时间（如 “2025\-10\-16 14:30”）、编码、ID、单号、状态等格式固定的字段，左对齐可突出字符顺序，方便快速识别信息；

4. 不固定长度类型字段

    1. 对齐方式：左对齐

    2. 适用场景：包含名称（如商品名称、客户名称）、操作列（如 “编辑 / 删除” 按钮组）等长度可变的内容，符合用户从左至右的阅读习惯，避免视觉跳跃；

### 4\.7、页面内容规范

> 页面文案提示规范
> 
> 页面文案需清晰传递信息、引导操作，同时保持语气克制，具体规则如下：
> 
> 1. 内容范围：需包含页面核心作用（如 “该页面用于管理商品基础信息”）、操作说明指引（如 “选择商品后，点击【批量修改】可统一调整价格”），复杂场景可补充示例案例（如 “示例：输入‘2024’可筛选当年新增商品”）；
>

### 4\.8、提示标准规范

> 不同场景提示样式选择规则
> 
> 为确保信息传递精准且不干扰操作，需根据提示类型与紧急程度，选择对应的展示样式：
> 
> 1. 飘红提示：适用于字段级错误或必填项遗漏；
> 
>     - 触发场景：用户输入内容不符合规则（如手机号格式错误、字符长度超限），或未填写必填字段直接点击下一步 / 保存时，在对应字段旁以红色文字提示问题；
> 
> 2. 弹出框提示：适用于关键操作确认或重要信息告知；
> 
>     - 触发场景：执行不可逆操作（如删除数据、取消订单）时，弹出确认框让用户二次确认；或系统出现影响业务的异常（如网络中断、数据加载失败）时，弹出提示告知原因与解决方案；
> 
> 3. Toast 提示：适用于轻量操作反馈，无需用户交互；
> 
>     - 触发场景：操作成功（如保存成功、提交成功）、轻微警告（如 “数据已自动保存”“所选内容无更新”）等，提示内容在页面顶部或中部短暂停留后自动消失，不阻断后续操作；
> 
> 提交操作时的错误定位规则
> 
> 用户提交表单（如新增 / 编辑数据）时，若存在未填写的必填字段，系统需按以下规则定位错误：

### 4\.9、页面跳转梳理

**页面跳转载体差异与使用标准**

根据操作复杂度、流程独立性，明确新页面、弹出框、抽屉页的适用场景，避免载体滥用导致体验混乱：

1. 新页面跳转：适用于独立且完整的业务流程，如 “商品新增”“订单详情查看”“用户信息编辑”；跳转后需保留原页面入口（如面包屑），支持用户回溯；

2. 弹出框：适用于轻量、短时的操作，如 “确认删除”“输入备注”“选择单个选项”；弹窗需居中显示，遮罩层弱化背景，操作完成后直接关闭并刷新原页面；

3. 抽屉页：适用于中等复杂度、需参考原页面信息的操作，如 “批量编辑商品属性”“查看关联订单列表”；抽屉页从右侧滑出，保留原页面可见，支持边操作边对照信息；

**认知与名词规范**

1. 解释层级划分：

    - 页面级解释：适用于复杂功能模块（如 “报表统计”“批量导入”），需在页面顶部添加简短说明，告知核心作用与操作流程；

    - 字段级解释：适用于专业术语、计算公式类字段（如 “库存周转率”“折后价”），需在字段旁添加问号图标， hover 时显示详细解释；

2. 专业名词梳理：统一业务相关名词表述（如 “加料” 不称 “附加料”，“规格” 不称 “型号”），形成名词对照表，避免跨模块歧义；

**字段与文案统一规范**

1. 页面标题：统一格式（如 “\[模块名\]\-\[操作\]”，例：“商品管理 \- 新增商品”“订单列表 \- 批量导出”），避免随意命名（如 “加商品”“订单导”）；

2. 操作按钮：核心按钮文案全局统一（如 “提交”“取消”“保存”“删除”），禁止同一功能用不同表述（如 “确认” 与 “提交” 混用）；

3. 英文统一：按钮、标题的英文翻译需固定（如 “提交” 对应 “Submit”，“取消” 对应 “Cancel”），避免同一文案多种译法；

**视觉样式全局规范**

需梳理并固定以下视觉元素标准，确保全系统视觉一致性：

- 颜色：统一主色、辅助色、警示色（如主色 \#1890FF，警示色 \#FF4D4F），禁止模块自定义颜色；

- 字体：全局使用同一字体（如 “微软雅黑”），标题、正文、提示文字的字号层级固定（如标题 16px，正文 14px）；

- 间距：统一元素间距标准（如按钮内边距 8px\*16px，模块间距 24px），避免疏密不均；

- 图标与图像：图标尺寸统一（如功能图标 24px*24px），图像压缩格式与分辨率固定（如商品图分辨率 *800px，格式 JPG）；

**交互层面统一规范**

1. 按钮状态：

    - 正常：默认色 \+ 无阴影；悬停：加深色 \+ 轻微阴影；点击：略缩 \+ 深色；不可用：灰色 \+ 无交互，文案灰度降低；

2. 输入行为：

    - 默认值：固定字段默认内容（如 “数量” 默认 1，“状态” 默认启用）；焦点状态：输入框边框高亮（如主色边框）；错误提示：字段旁飘红文字，无弹窗干扰；

3. 页面切换：

    - 切换等待：显示加载动画（如居中 spinner），不空白；过渡逻辑：先加载新页面数据，再隐藏原页面；切换动画：统一淡入淡出（时长 300ms），无复杂动画；

4. 组件动态效果：

    - 下拉组件：展开 / 收起动画时长 200ms，无卡顿；弹窗：弹出时居中渐显，关闭时渐隐，无偏移；

**响应式布局规范**

1. 滚动条：全局统一滚动条样式（如宽度 8px，圆角 4px，默认色 \#E5E7EB，hover 色 \#D1D5DB），禁止浏览器默认样式；

2. 屏幕缩放适配：

    - 支持屏幕分辨率范围（如 1366*768 至 1920*1080）；缩放时元素按比例适配，无重叠、溢出；小屏幕下优先折叠非核心模块（如侧边栏可收起），不挤压核心内容；
