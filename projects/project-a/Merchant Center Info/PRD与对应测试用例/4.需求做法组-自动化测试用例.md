# 商品中心-商品管理-组 自动化测试用例

> 由 PRD 需求测试用例按标题从 `2.商品中心-商品管理-组-自动化测试用例.md` 提取，不新增自动化步骤；规范见 [product-center-automation-test-case](.cursor/skills/product-center-automation-test-case/SKILL.md)。

## 组管理自动化套件约定

> 写入 `*-组-自动化测试用例.md` 顶部，**每条用例不再重复**。

## 登录与权限

- 使用执行计划绑定的测试账号登录商品中心
- 账号须具备组管理（规格/口味/做法/加料/套餐组）读写权限

## 数据命名

| 类型 | 格式 | 示例 |
|------|------|------|
| 新建组名 | `组名称-autocreate-{类型小写}-{正式编号}{场景后缀}` | `组名称-autocreate-spec-005b` |
| 新建明细名 | `{明细前缀}-autocreate-{类型}-{编号}` | `规格明细-autocreate-spec-004-01` |
| 数据依赖-单对象 | `TC_GRP_{类型}_{编号}` | `TC_GRP_SPEC_013` |
| 数据依赖-引用 | `{类型}_REF_{编号}` / 商品 `STD_REF_{编号}` | `TC_SPEC_GRP_REF_013` |
| 重复名校验 | 沿用正式用例反引号名 | `GRP_DUP`、`TASTE_DUP` |

- 执行前确认当前品牌下不存在将创建的同名的组/明细（或由平台 teardown 清理）

## 数据依赖用例（UI + 平台造数）

> 本文档 **仅含 UI 可执行用例**。接口造数/清理 **不写入本文档**，由执行计划完成。

- UI 用例写 **`数据标识`**、**`数据准备`**（一行指向执行计划）、**Readiness**、**`失败分类`**
- 步骤按固定组名/明细名/商品名查询定位，禁止「存在规格组 A」类模糊前置

## 导航入口

| 组类型 | 列表 | 新增 |
|--------|------|------|
| 规格组 | 商品管理 → 规格组 | 列表 → 新增 |
| 口味组 | 商品管理 → 口味组 | 列表 → 新增 |
| 做法组 | 商品管理 → 做法组 | 列表 → 新增 |
| 加料组 | 商品管理 → 加料组 | 列表 → 新增 |
| 套餐组 | 商品管理 → 套餐组 | 列表 → 新增（固定/组合搭配按用例） |

- 保存/确认按钮：组编辑页统一写「保存」或「确认」（与现网一致，以用例步骤为准）

## 步骤增强

- **禁止**「组名称或明细名称留空」「仅填组名称」「按需填写」等模糊步骤
- 必填项缺失：拆 `-A` 组名称为空 / `-B` 明细名称为空（单步骤仅测一项）
- 列表/查询：有已知关键字时用反引号具名
- 被引用/删除/同步类：写清 `数据标识` + Readiness

### 用例编号：TC-需求4-003

用例标题：新增做法组仅填必填项保存成功

优先级：P0

执行类型：UI

执行策略：SINGLE_SCENARIO

起始页面：
- 导航：商品管理 → 做法组 → 新增
- 就绪条件：页面出现「组名称」或组名称输入框

前置条件：
1. 已登录商品中心，具备组管理权限。
2. 从起始页面进入做法组新增页。

测试步骤：
1. 「组名称」输入 `组名称-autocreate-mth-003`。
2. 点击「添加做法明细」。
3. 「做法明细名称」输入 `做法明细-autocreate-mth-003-01`。
4. 「加价」输入 `0.00`（或保持默认）。
5. 点击「确认」保存明细。
6. 点击「保存」。
7. 返回列表，组名称查询框输入 `组名称-autocreate-mth-003`，点击「查询」。

预期结果：
1. 出现保存成功提示，无报错弹窗。
2. 列表/详情与提交一致。
3. 关键字段与步骤输入一致。
