# 公共平台晋级执行方案

版本：1.0（2026-09-01）  
目标：补齐 C-001～C-009、企业治理能力、用户价值指标，并完成不同 `applicationId` 的真实试点，使公共平台具备申请 `GA/平台级成熟` 的可审计依据。  
当前状态：`in-progress-with-findings`；W0～W2 已完成静态/合同验证，W3 正在建立指标基线；W4 受迁移闭环阻断，W5 跨应用试点仍为 `deferred`。本文件不代表平台已 GA。

## 1. 决策三问

**级别：必须**

**目的**：解决公共平台目前仅有 Merchant Center 局部接入、缺少标准收据、负向合同、企业治理、价值指标和跨应用真实证据的问题，避免把单项目结果误报为通用平台完成。

**预期结果**：形成公共合同测试收据、企业治理验收收据、30 天价值指标基线、至少一个不同 `applicationId` 的可逆端到端试点，以及一份 Go/No-Go 评审记录。全部条件满足后，平台才可从 `deferred/not-ready` 晋级 `GA`。

**后续影响**：执行期间不重跑 Merchant Center 已通过用例；跨应用试点须由用户明确启动。公共层、试点适配器和证据目录会新增开发、测试、审计和存储成本；Merchant Center 自身交付继续独立裁决。

## 2. 范围与不变项

### 范围

- `public-core`：C-001～C-009、统一编译/授权/收据/状态/批次/检查点、系统无关负向测试。
- `project-adapter`：Merchant Center 适配器合同、输出根目录和现有模块接入验证。
- `pilot-adapter`：一个与 `merchant-center` 不同的真实 `applicationId`，覆盖认证、上下文、业务操作、断言、清理和证据。
- `domain-asset`：平台发布清单、指标定义、权限矩阵、保留策略和评审记录。
- `generated-evidence`：检查点、合同测试结果、试点收据、指标快照和 Go/No-Go 报告。

### 不变项

- 不导出隐藏思维链、密码、Token、Cookie、授权头或浏览器存储。
- 不把截图、汇总通过数、旧 Allure 状态或历史索引当作标准收据。
- 不因平台缺口改变 Merchant Center 既有通过结果；只有用例/实现/上下文/产品行为变化才触发定向重验。
- 不在 Merchant Center 项目复制公共状态机、报告裁决或批次门禁。

## 3. 阶段与工作单元

| 阶段 | 工作单元 | 主要动作 | 产物 | 通过门槛 | 失败处理 |
|---|---|---|---|---|---|
| 0. 基线冻结 | W0 | 读取最终目标、公共合同、项目依赖；生成候选/治理/选择集指纹 | `公共平台晋级执行检查点-20260901.json` | 输入清单、版本和当前 `deferred` 状态完整 | 缺文件或指纹不一致则停止 |
| 1. 公共合同 | W1 | 实现/校验 C-001～C-007；运行系统无关合同测试 | 合同测试和负向测试收据 | 全部通过；每条失败有分类和证据 | 修复技术/环境问题，不改判产品失败 |
| 2. 企业治理 | W2 | 验证 C-008：RBAC、敏感证据访问、不可篡改审计、保留、删除、恢复/回滚 | 权限矩阵、审计日志、治理收据 | 越权被阻断；操作可审计；恢复可验证 | 缺证据保持 `not-ready` |
| 3. 价值指标 | W3 | 验证 C-009 遥测；先通过事件去重、时间窗口、分母完整性校验，再建立证据定位、诊断、重跑、人工介入、复用等 30 天基线 | 指标字典、质量报告、分母说明、基线快照 | 每项有定义、分母、采样范围、责任人、更新时间；质量报告无重复、越窗或缺失分母 | 数据缺口登记为 evidence-gap |
| 4. Merchant Center 接入 | W4 | 只执行适配器合同和接入校验；核对输出隔离 | adapter contract receipt、路径越界负向收据 | 适配器只提供领域映射；`moduleDeliveryBlocked=false` | 项目层修复，不修改公共裁决 |
| 5. 跨应用试点 | W5 | 用户明确授权后，选择不同 `applicationId`；运行一个可逆最小场景，覆盖认证→上下文→操作→断言→清理 | 执行意图、授权、逐用例收据、清理收据 | 不同应用 ID；至少一个用例完整收据 | 认证/环境问题分类停止，不重试冻结试点 |
| 6. 晋级评审 | W6 | 运行公共最终门禁，汇总合同、试点、治理和指标证据 | Go/No-Go 报告、批准记录、指纹 | 全部 Go 条件满足才可 GA，否则 `not-ready/deferred` | 记录缺口和恢复条件 |

## 4. 建议执行顺序与命令

### 4.1 公共合同验证（只读/合成数据）

在公共平台目录执行，使用合成或隔离结果目录：

```text
npm run typecheck
npm run boundary
npm run architecture:check
npm run verify-reference
npm run test:acceptance
npm run test:business-rule-trigger
npm run test:migration-closure
```

这些命令只验证公共合同、架构和参考基线，不启动 Merchant Center 业务页面。

### 4.2 项目接入验证（不执行业务）

```text
npm run compile -- --plan=<project-plan.json> --manifest=<project-manifest.json>
npm run build -- --plan=<project-plan.json> --manifest=<project-manifest.json>
npm run lifecycle:project -- --project-adapter=<adapter.json>
```

必须确认输出写入项目适配器声明的目录，拒绝 `..` 越界；缺少适配器合同不得进入试点。

### 4.3 跨应用试点（必须另行明确授权）

仅在用户明确启动、目标系统认证和适配器就绪后执行：

```text
npm run flow -- --plan=<pilot-plan.json> --manifest=<pilot-manifest.json>
npm run flow -- --plan=<pilot-plan.json> --manifest=<pilot-manifest.json> --execute
```

试点必须使用最小可逆范围；每批保存检查点，失败后从首个未完成单元恢复。

### 4.4 最终平台门禁

```text
npm run verify:system-test-platform
```

返回 `FINAL_GOAL_NOT_MET` 时，平台保持未完成；该结果不得转译成 Merchant Center 业务失败。

## 5. C-001～C-009 验收矩阵

| 合同 | 必须证明 | 证据 |
|---|---|---|
| C-001 | 每个操作/断言/失败均有唯一收据，缺证据不得通过 | receipt index、失败诊断收据 |
| C-002 | 上下文守卫和短期授权在认证/造数/浏览器前阻断错误场景 | guard/grant/负向收据 |
| C-003 | 增量/整改与全量互斥；批次、选择集和恢复不漂移 | mode-gate、checkpoint 收据 |
| C-004 | 状态独立且三条分母公式守恒 | arbitration、denominator 报告 |
| C-005 | 创建对象有服务端 ID；finally 清理；UI/API 零残留 | CRUD/cleanup 收据 |
| C-006 | 公共核心、适配器、系统无关负向合同和输出隔离成立 | boundary/adapter/negative 收据 |
| C-007 | 实时事件幂等、可恢复、不中断丢失 | event stream/replay 收据 |
| C-008 | RBAC、敏感证据、审计、保留、删除、恢复和回滚成立 | governance 收据 |
| C-009 | 价值指标可计算、可下钻、可追责，至少 30 天基线 | metric dictionary/baseline 快照 |

## 6. 暂停、重试与恢复

- 每个工作单元开始前写入检查点，成功后写入完成指纹和产物清单。
- 连接重置、超时、429 等瞬态故障按 5/15/30/60 秒有界重试；非幂等操作先查询是否已生效，不盲目重放。
- 同一实现的确定性失败不得在无实现指纹变化时再次启动浏览器；冻结的跨应用试点不重复执行。
- 缺少真实目标系统、认证、适配器或完整收据时，W5 保持 `deferred`，W6 不得给出 GA。
- 任何敏感信息命中均停止发布，保留脱敏诊断，不写入报告或检查点。

## 7. Go/No-Go

### Go（全部满足）

1. C-001～C-009 及系统无关负向测试全部通过。
2. Merchant Center 适配器和不同 `applicationId` 真实试点均有完整收据。
3. 错误上下文、过期/撤销授权、越权 caseId、模式混用、选择集漂移和输出越界均能前置阻断。
4. 报告支持 `caseId + runId + receipt` 下钻，状态和分母守恒。
5. 批次可从检查点恢复，且不复用不匹配收据。
6. RBAC、审计、保留、合规删除、恢复/回滚有独立收据。
7. 用户价值指标已建立至少 30 天基线并可下钻。
8. 平台与项目裁决分离，项目交付状态不被平台 deferred 错误阻断。

### No-Go

任一 Go 条件缺失，平台状态为 `not-ready` 或 `deferred`；必须登记缺口 ID、责任人、恢复条件和下一次评审触发条件。No-Go 不改变既有 Merchant Center 通过结果。
