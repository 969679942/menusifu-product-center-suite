# 反向场景证据队列的当前性

范围为 project-adapter 与 generated-evidence。队列消费公共 `readJsonEvidence` 与 `publishImmutableArtifact`，不复制公共发布和快照协议。

输入必须具备非空、唯一的场景清单，逐场景证据数量与汇总必须一致。缺失、损坏、不可读或结构无效时，当前 JSON/Markdown 发布明确阻断，未知汇总为 null；先前观察和新的阻断观察均由公共快照保留。诊断仅存原因码，不保存源字节或异常文本。

成功生成只表示静态投影完成。它绑定当前输入内容指纹，治理任务消费时重新核对输入和完整投影；旧文件存在、已生成的 blocked 旁路诊断或被修改的计数不能授权本次静态完成。修复输入后可重新生成，旧阻断诊断保留为历史，当前状态以主报告为准。

本队列不验收真实业务收据，不以证据声明数量证明运行覆盖，不启动业务执行，不作废或重跑历史通过用例。来源报告本身的生产链及证据文件的当前哈希仍由各自审计负责。

上游商品中心就绪报告同样使用公共读取与快照发布：公共场景目录、项目映射和审计库存均校验结构与唯一身份，项目映射必须属于该目录。异常替换主报告为 blocked，因而即使下游队列尚未重建，治理读取也会拒绝原队列；输入恢复后再正常投影。合法输入以内容指纹登记，完整证据文件的运行态验收仍未由静态投影代替。

队列生成和治理消费均重新读取适配器独立配置的目录、映射与审计三个输入，以公共 `verifyJsonInputCurrentness` 核对就绪报告的全部声明。原始输入变化但上游尚未重建时，旧队列立即失去当前静态完成资格；生成入口发布 `REVERSE_SCENARIO_READINESS_STALE`，不会自行更新旧报告指纹来掩盖未重建的投影。
