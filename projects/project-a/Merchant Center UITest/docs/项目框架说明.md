# Merchant Center UI 自动化框架说明

## 1. 文档目标

本文档介绍当前 Merchant Center 自动化项目的整体设计、模块职责与扩展方式。

本项目基于 POS2.0 自动化框架迁移而来，采用 Playwright Test + TypeScript，目标是：

- 用稳定、可复用的 Page Object 和 Flow 表达页面能力与业务意图
- 用统一的测试分层承载 smoke、业务回归、页面契约校验
- 用中文步骤和 Allure 报告提升执行可读性
- 用清晰边界保证后续可以持续交给 Codex 或人工维护

## 2. 技术栈与运行方式

### 2.1 核心技术

- 测试运行器：`@playwright/test`
- 语言：`TypeScript`
- 报告：`allure-playwright` + `allure-commandline`
- 运行浏览器：`chrome`

### 2.2 关键脚本

- `npm test`：运行全部测试
- `npm run test:smoke`：仅运行 smoke 测试
- `npm run test:e2e`：仅运行 e2e 测试
- `npm run test:headed`：以 headed 模式运行
- `npm run explore`：探索页面并生成初稿测试用例
- `npm run codegen`：打开 Playwright Codegen
- `npm run allure:generate` / `npm run allure:open`：Allure 报告

### 2.3 运行配置

主配置文件是 `playwright.config.ts`：

- 测试目录：`tests/`
- 全局初始化：`tests/setup/global.setup.ts`
- 登录态准备：`tests/setup/auth.setup.ts` → `output/auth-state.json`；全局 teardown 结束后自动删除
- 默认入口：`https://cc-fe.balamxqa.com`

## 3. 项目目录结构

```text
merchant-center/
├─ docs/                      文档
├─ fixtures/                  Playwright fixture 扩展
├─ flows/                     业务流程封装
├─ pages/                     页面对象层
├─ scripts/                   页面探索脚本
├─ test-data/                 环境数据、认证信息
├─ tests/
│  ├─ e2e/                    业务回归 / 页面契约
│  ├─ generated/              Agent / 探索输出草稿
│  ├─ setup/                  全局初始化与登录态
│  ├─ smoke/                  稳定性冒烟
│  └─ seed.spec.ts            Playwright Test Agents 种子入口
├─ utils/                     纯工具与公共辅助
├─ AGENTS.md                  项目自动化约束
├─ package.json
└─ playwright.config.ts
```

## 4. 框架分层设计

- `pages/`：页面结构、locator、单页动作与读取
- `flows/`：业务意图、多步编排、选择策略
- `tests/`：验证结果
- `fixtures/`：注入页面对象
- `test-data/`：环境与样本数据
- `utils/`：公共基础设施

详细 POM 规范见 `docs/page-object-guidelines.md`。

## 5. 商户中心主流程

```text
访问目标 URL
  -> 如未登录则跳转 OAuth 登录页
  -> 输入账号密码
  -> 回到 cc-fe 域名
  -> 如出现「选择商户」则选择目标商户并确认
  -> 进入目标业务页（如图片管理）
```

对应模块：

- `pages/auth-login.page.ts`：OAuth 登录页动作
- `pages/auth-login.page.ts` 中的 `MerchantSelectionPage`：商户选择弹窗
- `flows/auth.flow.ts`：组合登录与商户选择
- `pages/brand-picture.page.ts`：图片管理页

## 6. Playwright Test Agents

Agent 定义位于：

- `.codex/agents/`
- `.claude/agents/`
- `.claude/prompts/`

使用说明见 `docs/Playwright-Test-Agents-中文使用文档.md`。

种子入口为 `tests/seed.spec.ts`，会先建立 OAuth 登录与商户上下文。

## 7. 凭证配置

优先级：

1. 环境变量：`MC_USERNAME` / `MC_PASSWORD` / `MC_MERCHANT` / `MC_BRAND_ID`
2. 本地秘密源：`..\.secrets\runtime.env`

请勿将真实密码、token、cookie 或 storageState 提交到版本库。

## 8. 与 POS2.0 的差异

| 项目 | POS2.0 | Merchant Center |
|------|--------|-----------------|
| 认证 | 授权页 + 员工口令 | OAuth + 商户选择 |
| 入口 | 内网 POS 首页 | Cloud Platform SPA |
| 导航 | 禁止 deep link | 允许 deep link，但需先完成认证 |
| iframe | 大量 iframe 场景 | 当前以单页 SPA 为主 |

## 9. 扩展建议

1. 在 `pages/` 下为新模块创建页面对象
2. 在 `flows/` 下组合业务步骤
3. 在 `tests/smoke/` 验证可达性
4. 在 `tests/e2e/` 验证业务规则
5. Agent 生成草稿先放 `tests/generated/`，审查后再上移
