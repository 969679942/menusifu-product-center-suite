# 商品中心统一合同维护设计

## 目标

由 Codex 维护模块源文件和生成流程，人工只审核差异、规则队列和发布记录。聚合合同继续作为唯一机器事实源，但不作为人工或 AI 的日常编辑入口。

## 架构

合同分为四层：原始 UI/API/PRD 证据、类型化模块源定义、自动生成的模块视图与索引、全局聚合合同。模块源定义只维护模块边界、路由、实体、PRD 匹配别名、规则前缀和跨路由映射，不复制原始证据。

九个能力模块覆盖 34 条路由且每条路由只能有一个主模块。API 操作根据模块内 UI→API 映射自动归属；无映射的 API、全局规则和未解决证据进入共享视图。

## 读取流程

查询先读取轻量 manifest，再根据 ID、路由、实体、模块或 operationKey 进入索引，最后只读取目标模块视图。只有需要复核证据时才读取聚合合同或原始证据。

## 维护流程

Codex 修改模块定义或导入证据后执行构建、校验、差异和合同测试。人工审核差异与评审队列后，通过显式发布命令提升基线；发布记录保存版本、合同指纹、审核人和摘要，不保存任何凭据。

## 安全与门禁

模块路由重复、路由未归属、SOP 未归属、无来源记录、未确认规则生成断言、追溯缺口、敏感信息和发布审核人缺失均阻断流程。删除事实使用差异记录保留历史，不在模块视图中静默消失。

## 验收

- 34 条路由唯一归属九个模块。
- 41 条生产 SOP 均能解析到模块。
- 支持按模块、路由、实体、ID 和 API operationKey 查询。
- 快照记录使用 64 位 SHA256，不重复保存完整记录。
- 发布必须提供与当前合同版本一致的版本和非空审核人。
- 全量合同测试、TypeScript、安全扫描和基线差异通过。
