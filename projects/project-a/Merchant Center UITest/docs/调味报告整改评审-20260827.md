# 调味报告整改评审

## 结论

本轮已完成公共报告层、调味报告适配器、状态裁决和绑定审计整改，但调味业务绑定仍未闭环。现有 Allure 报告不能作为当前通过报告：原始结果显示 `82/82 passed`，完整性审计发现 `37` 条全绿但绑定不完整，`33` 条变更语义缺少 `业务操作：` 步骤。

因此当前结论为：`报告能力整改完成，调味业务用例整改未完成，当前报告作废为历史证据`。商品和组方案仍保持暂停，本轮没有重跑业务用例。

## 下一轮建议

### 必须：重建调味业务绑定

- **目的**：让每条变更、负向、边界、重复和下发用例都执行真实 UI 业务操作，并以 UI/API/清理收据闭环。
- **预期结果**：覆盖审计 `findings=0`；每条变更类 Allure 都出现对应中文 `业务操作：` 步骤；新执行收据才能进入当前通过分母。
- **后续影响**：只重跑受实现指纹或用例指纹影响的调味用例；既有 82 条历史结果不恢复、不自动重算为通过；运行时长会因造数和清理增加，但能消除假通过。

### 必须：完成平台迁移门禁

- **目的**：解除公共平台 readiness 的迁移未完成阻断。
- **预期结果**：`npm run verify:system-test-platform` 完整执行并给出正式平台结论。
- **后续影响**：影响平台发布状态，不改变商品/组暂停范围，也不应触发无关业务重跑。

### 暂不建议：重跑当前 82 条全量

- **目的**：当前没有足够收益，因为 55 条绑定仍会被门禁拒绝，且旧报告已被完整性审计标为历史证据。
- **预期结果**：不会产生可采信的新闭环，只会增加环境、数据和清理成本。
- **后续影响**：不改变已通过或历史结果；待绑定整改和合同门禁通过后，再按指纹影响范围定向执行。

## 人工复核清单

1. 打开 `allure-report3` 时以完整性审计为准，不以 Allure 首页全绿为准。
