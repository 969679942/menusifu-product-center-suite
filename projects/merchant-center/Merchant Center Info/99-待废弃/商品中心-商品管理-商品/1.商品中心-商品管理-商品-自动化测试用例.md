## 数据命名

| 类型 | 格式 | 示例 |
|------|------|------|

| 加料/套餐新建名 | `商品名称-autocreate-{pkg\|add}-{编号}{场景后缀}` | `商品名称-autocreate-add-006b` |

| 数据依赖-单对象 | `TC_DATA_{STD\|PKG\|ADD}_{正式编号}` | `TC_DATA_STD_068` |
| 数据依赖-引用链 | `{类型}_REF_{编号}` / `{类型}_GRP_{编号}` | `ADD_REF_027`、`ADD_GRP_027`、`STD_REF_027` |
| 数据依赖-菜单引用 | `{类型}_REF_{编号}` + `MENU_REF_{编号}` | `STD_REF_070`、`MENU_REF_070` |
| 组合查询种子 | `TC_QUERY_{STD\|PKG\|ADD}_001` | `TC_QUERY_STD_001` |

- 执行前确认当前品牌下不存在将创建的同名字商品（或由平台 teardown 清理）

## 数据依赖用例（UI + 平台造数）

> 本文档 **仅含 UI 可执行用例**（`执行类型：UI` / `E2E`）。接口造数/清理 **不写入本文档**，由执行计划或平台脚本完成。

正式用例前置若写「列表中存在…」「已存在…」「已被…引用」：

1. UI 用例须写清 **`数据标识`**（固定命名，便于列表检索）。
2. **`数据准备`** 一行指向执行计划造数（不在本文档展开 API 步骤）。
3. 前置含 **Readiness 门禁**：查不到目标 → block/skip，不判产品缺陷。
4. UI 步骤 **按名称查询定位**，禁止「在列表找一条满足条件的商品」。

### Readiness 门禁

- 若 `数据标识` 目标在列表查不到 → **环境未就绪（block/skip）**，不判定为产品缺陷。

### 失败分类

| 现象 | 分类 |
|------|------|
| Readiness 未通过 / 造数未完成 | 环境/数据问题 |
| 业务断言不符 | 产品缺陷 |

### 平台种子数据

- 原料、行业商品库、打印档口等：执行计划确认种子存在；不存在则 block。

## 表单约定

- 保存按钮文案：**保存**
- 起售数量：在「高级设置」折叠区内，需先展开（标准/套餐）；加料商品无起售数量
- 商品分类：非必填，未特别说明时不选择
- 单规格默认；非称重除非用例明确要求

## 负向用例

- 以「仍停留当前页 + 无保存成功提示 + 字段校验提示」为主
- **商品名称首尾含空格：保存失败**（见 BR-FMT-001），不可保存成功后自动去除
- 需要时增加列表按名称查询无新记录

## 废弃

- `TC-ITEM-STD-060`、`TC-ITEM-PKG-066`：勿自动化执行

### 用例编号：TC-ITEM-STD-001

用例标题：标准商品创建页展示正确

优先级：P0

执行类型：UI

执行策略：SINGLE_SCENARIO

起始页面：
- 导航：商品管理 → 商品
- 就绪条件：页面出现商品列表表格

前置条件：
1. 已登录商品中心，具备商品管理权限。
2. 从起始页面进入商品列表页。

测试步骤：
1. 点击「新增商品」，进入商品类型选择页。
2. 选择「标准商品」，进入标准商品创建页。
3. 查看左侧导航及基础信息区域。
4. 依次点击左侧导航：基础信息、商品属性、展示设置、材料信息、统计标签、商品描述。

预期结果：
1. 商品类型选择页展示「标准商品」「套餐」「配菜/加料」三个选项。
2. 成功进入标准商品创建页。
3. 页面包含导航栏、基础信息、商品属性、展示设置、材料信息、统计标签、商品描述等模块，行业名称输入框置灰不可手动输入。

### 用例编号：TC-ITEM-STD-008

用例标题：商品名称超长及特殊字符保存后自动格式化

优先级：P0

执行类型：UI

执行策略：SINGLE_SCENARIO

起始页面：
- 导航：商品管理 → 商品 → 新增商品 → 标准商品
- 就绪条件：页面出现「商品名称」输入框

前置条件：
1. 已登录商品中心，具备商品管理权限。
2. 从起始页面进入标准商品创建页。
3. 当前品牌下不存在与本次格式化后名称可能冲突的同名商品。

测试步骤：
1. 「商品名称」输入 `商品名称-autocreate-008  连  空格  Test01@#` 后接字符使总长度超过 100（首尾不含空格；中间可含连续空格；含中文、字母、数字；可含 `@`、`#` 或 emoji 用于验证过滤）。
2. 「起售数量」输入 `1`。
3. 「标准价」输入 `10.00`。
4. 点击「保存」。
5. 进入该商品详情/编辑页，记录回写的商品名称 `SAVED_NAME`。
6. 返回列表，按 `SAVED_NAME` 查询。

预期结果：
1. 出现保存成功提示，无报错弹窗。
2. 详情/编辑页回读的 `SAVED_NAME` 长度不超过 100 字符；连续空格已规范为单个空格；不支持的特殊字符（如 emoji、`#` 等，以 BR-FMT-004 为准）未保留。
3. 列表按 `SAVED_NAME` 查询有且仅有 1 条记录；列表与详情展示名称均为 `SAVED_NAME`。

### 用例编号：TC-ITEM-STD-009

用例标题：POS名称和送厨名称超长及特殊字符保存后自动格式化

优先级：P1

执行类型：UI

执行策略：SINGLE_SCENARIO

起始页面：
- 导航：商品管理 → 商品 → 新增商品 → 标准商品
- 就绪条件：页面出现「商品名称」输入框

前置条件：
1. 已登录商品中心，具备商品管理权限。
2. 从起始页面进入标准商品创建页。
3. 当前品牌下不存在测试商品 `TC_POS_FMT_009`。

测试步骤：
1. 展开「高级设置」。
2. 「商品名称」填写 `TC_POS_FMT_009`（首尾不含空格）。
3. 「POS 名称」填写超过 20 个字符的内容（**首尾不含空格**；中间可含连续空格；含字母、数字、中文及特殊字符）。
4. 「送厨名称」填写超过 20 个字符的内容（**首尾不含空格**；中间可含连续空格；含字母、数字、中文及特殊字符）。
5. 「起售数量」填写 `1`；「标准价」填写 `10.00`。
6. 点击「保存」。
7. 返回列表，商品名称查询框输入 `TC_POS_FMT_009`，点击「查询」，进入编辑页，分别记录 `POS_SAVED`。
8. 返回列表，商品名称查询框输入 `TC_POS_FMT_009`，点击「查询」，进入编辑页，分别记录 `KITCHEN_SAVED`。

预期结果：
1. 保存成功，无报错拦截。
2. `POS_SAVED`、`KITCHEN_SAVED` 按系统规则格式化（超长截断、连续空格规范、不支持的特殊字符未保留）；**不含首尾空格**。
3. 列表按 `TC_POS_FMT_009` 可查询到该商品。
