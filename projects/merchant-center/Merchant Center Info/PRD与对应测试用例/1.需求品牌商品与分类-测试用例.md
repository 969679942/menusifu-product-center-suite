## S01 商品列表

### 用例编号：TC-需求1-001

用例标题：加料商品列表按名称类型分类状态组合查询成功

所属模块：商品管理 → 商品 → 查询

优先级：P1

来源：PRD 5.1.1 查询条件；BR-FMT-009

前置条件：
1. 商品列表中存在符合查询条件的加料商品。
2. 已进入商品列表页。

测试步骤：
1. 商品名称输入关键字。
2. 商品类型选择「加料/配菜」。
3. 按需选择分类、状态后点击查询。

预期结果：
1. 列表仅返回符合条件的加料商品。
2. 查询后列表自动定位到结果首页。

### 用例编号：TC-需求1-004

用例标题：加料商品状态变更后需下发到门店终端才生效

所属模块：商品管理 → 商品 → 加料商品

优先级：P1

来源：BR-ARCH-004、BR-ITEM-050

前置条件：
1. 商品当前已在门店终端可售。
2. 已完成商品状态变更操作但尚未下发。

测试步骤：
1. 在终端查看该商品当前可售状态。
2. 执行菜单或商品下发。
3. 再次在终端查看该商品状态。

预期结果：
1. 未下发前，终端状态不随品牌侧状态变更立即生效。
2. 下发完成后，终端状态与品牌侧最新状态一致。

### 用例编号：TC-需求1-005

用例标题：加料商品重置查询后页面恢复初始状态

所属模块：商品管理 → 商品 → 查询

优先级：P1

来源：BR-FMT-009

前置条件：
1. 已进入商品列表页。
2. 当前列表存在查询条件或非首页分页状态。

测试步骤：
1. 商品名称输入 `ADD_QUERY`，商品类型选择「加料/配菜」，按需选择分类、状态后点击查询。
2. 点击重置。
3. 查看查询区和列表状态。

预期结果：
1. 商品名称、商品类型、商品分类、商品状态等查询条件恢复初始状态。
2. 列表恢复到初次进入页面时的默认状态并自动定位到首页。

### 用例编号：TC-需求1-018

用例标题：商品展示列设置后列表仅展示所选列

所属模块：商品管理 → 商品 → 商品列表

优先级：P1

来源：XMind已有 ← 标准商品 / 展示 / 页面展示 / 商品展示列设置，商品列表只展示选择的列

前置条件：
1. 已进入商品列表页面。

测试步骤：

2. 勾选「分类」「规格」「标准价」。

4. 取消勾选「规格」。

1. 展示列设置弹层打开成功，固定列「选择」「图片」「商品名称」「商品类型」「操作」始终展示且锁定位置。
2. 列表展示固定列以及「分类」「规格」「标准价」。
3. 取消勾选「规格」后，列表不再展示规格列，其余已选列保留。

### 用例编号：TC-需求1-019

用例标题：商品列表支持按名称、类型、分类、状态组合查询

所属模块：商品管理 → 商品 → 查询

优先级：P0

来源：PRD明确 ← 5.1.1 品牌商品 / 商品列表页 / 查询条件；XMind已有 ← 标准商品 / 查询

前置条件：
1. 商品列表中存在名称包含 `D1_QUERY` 的标准商品、套餐商品和加料商品。
2. 其中存在一条启用状态的标准商品 `D1_QUERY_STD_001`，归属叶子分类 A。

测试步骤：
1. 进入 品牌商品 → 商品 列表页。
2. 商品名称输入 `D1_QUERY`。
3. 商品类型选择「标准商品」。
4. 商品分类选择叶子分类 A，商品状态选择「启用」。
5. 点击查询。

预期结果：
1. 列表仅返回同时满足名称、商品类型、商品分类、商品状态条件的数据。
2. 查询结果包含 `D1_QUERY_STD_001`，且不展示套餐商品、加料商品或其他分类/状态不匹配的数据。
3. 执行查询后，列表自动定位到结果首页。
