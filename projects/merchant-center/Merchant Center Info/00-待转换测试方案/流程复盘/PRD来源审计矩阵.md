## 1. 来源准入规则

### 允许直接形成需求（`optimized-confirmed`）

- 用户明确确认、批准或要求执行的优化结论。
- 后续项目文件、审计结果、执行收据或状态索引已验证，且没有被撤销的结论。
- 公共平台合同中已经明确的通用门禁和状态规则。

### 允许作为背景或约束（`validated-problem-background`）

- 优化前暴露的问题，且后续证据证明问题真实存在。
- 只能写入背景、反模式、风险或约束，不能直接写成“系统应当”的现行方案。

### 不得形成现行需求

- 已被后续结论替代的探索性方案。
- 只有助手提出、没有用户确认或证据验证的建议。
- 已撤销、回滚或与当前指纹不一致的实现结果。
- 与 Merchant Center 流程无关的任务和重复委派。

## 3. 逐段检查结果

- PRD 的规范性需求不以 `019f7e48…` 这条优化前 TestOps 探索线程作为唯一来源。
- 优化前内容只允许以“历史问题背景、已替代方案或反模式”出现。
- `587/587` 探针、侧边栏不可见等旧口径在 PRD 中只能作为被纠正的历史问题，不能作为当前通过标准。
- 当前项目指标、平台 `deferred` 状态和日期空档必须带生成时间，不能从旧对话直接继承。
- 每条 FR 均有来源类别；详细 threadId 映射仍保存在 `对话证据索引.json` 的 `prdTraceability`。

## 4. 历史执行状态复核

### 优先级与产品层归属

| FR 范围 | 优先级 | 产品层归属 | 处理原则 |
|---|---|---|---|
| FR-001～FR-003、FR-005～FR-008、FR-010、FR-013、FR-015 | P0 | `domain-asset` + 产品结果可信度 | 已执行项作为基线；未执行部分按来源和收据补证 |
| FR-011、FR-012、FR-017～FR-022 | P0 | `public-core` 合同依赖 | PRD 只描述用户结果，技术规则见公共平台合同 |
| FR-004、FR-009、FR-014、FR-016、FR-023、FR-025、FR-026 | P1 | 治理增强/平台依赖 | 已执行范围有限或公共条件暂缓，不阻断模块交付 |
| FR-024 | P2 | 产品化非功能 | 作为长期运营增强，不改变历史事实 |

| FR 范围 | 历史执行状态 | 说明 |
|---|---|---|
| FR-001～FR-003、FR-005～FR-008、FR-010～FR-013、FR-015 | `executed-verified` | 对话中已执行或确认，且有项目文件、审计结果、索引或收据旁证 |
| FR-004、FR-009、FR-014、FR-016 | `executed-scoped` / `deferred-platform` | 已形成或局部执行，但关系图、外部触发或跨应用试点仍有限制 |
| FR-017～FR-022 | `gap-audit` | 本轮根据公共合同复核补出的缺口，历史对话未证明已经完整执行；技术细节已拆到公共合同文件 |
| FR-023 | `gap-audit` | 已有一次性备份修复旁证，但完整 dry-run、回滚和审计合同未被历史证明 |
| FR-024 | `gap-audit` | 产品化非功能和报告交互尚未作为已执行能力验收 |
| FR-025～FR-026 | `gap-audit` | 行业对标发现的企业治理和用户价值缺口，历史未证明已经执行 |

因此，PRD 中的 FR-001～FR-016 是已执行优化的状态化归纳；FR-017～FR-026 是差距登记，不应被表述为已经完成的历史结果，也不构成对前述已执行优化的再次实施要求。

## 5. 验收门禁

只有同时满足以下条件，才允许发布新的 PRD 版本：

1. 每条规范性 FR 至少有一个 `optimized-confirmed` 或 `gap-audit` 来源。
2. 仅由优化前对话支持的规范性 FR 数量为 0。
3. 被替代方案全部登记到《PRD排除与替代清单.md》。
4. 每条需求能够反向定位到 threadId、公共合同或本轮缺口审计记录。
5. PRD 修改不改变历史对话记录，不触发业务用例重跑。
