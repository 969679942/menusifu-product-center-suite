# 公共平台合同与差距登记

版本：1.1（2026-09-01 行业对标补充）  
归属：`public-core`；本文件不是 Merchant Center 业务 PRD。  
关联：`流程优化PRD.md` FR-011、FR-012、FR-014、FR-016～FR-026。

## 1. 文档职责

本文件只定义跨方案、跨系统复用所需的公共技术合同和当前差距。Merchant Center 适配器只提供路由、字段、业务操作、断言、数据和清理映射，不复制本文件中的状态机、报告裁决、批次门禁或授权逻辑。

## 2. 公共合同

### C-001 收据完整性

- 每个声明的业务操作必须有且只有一个 operation receipt，或一个明确的终止失败/中断 receipt。
- 每个断言收据必须包含 expected、actual、观察通道、验证权威、比较结果和最终状态。
- 失败诊断必须包含人类可读结论、标准分类、阶段、超时/定位/认证指标、技术详情和证据，并绑定到最深层失败步骤。
- 截图、汇总通过数、`observed=true` 或共享文件路径不能单独授权通过。

### C-002 上下文守卫与执行授权

- 业务操作、造数和断言前验证路由、语言、角色、租户、服务端 ID/唯一业务身份及观察通道。
- 正式执行授权必须绑定 `applicationId + runId + 精确 caseId 集合`，并具备短期有效期、撤销和越权校验。
- 授权失效、撤销或越权必须在认证、造数和浏览器启动前失败。
- 上下文守卫必须生成独立收据，错误上下文不得产生业务操作或通过结论。

### C-003 执行模式和批次门禁

- `incremental/repair` 与 `full-regression` 是互斥模式。
- 整改模式必须经过静态合同、优化计划、canary 收据，并达到 `ready-for-batch` 后才能批量放量。
- 全量回归不消费 canary/batch 结果；单组失败不得阻断无关分组。
- 每批保存检查点；恢复时仅复用当前指纹、当前选择集下已有完整收据的批次。

### C-004 状态裁决和分母

- 独立保存 `formalDisposition`、`executionStatus`、`evidenceStatus`、`applicabilityStatus`、`reuseStatus`、`verificationStatus` 和 `actionRequired`。
- 至少区分 `completed-with-findings`、`blocked`、`failed`、`evidence-incomplete`、`deferred`。
- 就绪分母必须满足：`planned = executionEligible + classifiedExclusions`、`executionEligible = executed`、`executed = passed + failed`。
- 技术、环境、证据阻断不能自动变成产品失败；旧索引、Allure 原始状态和汇总布尔值不能单独裁决当前状态。

### C-005 CRUD 与清理

- 创建对象后立即记录服务端 ID 或唯一业务身份。
- 清理必须在 `finally` 执行；清理后按用例要求同时验证 API 与 UI 零残留。
- 清理失败是独立证据和失败分类；全局“零残留”汇总不能替代逐用例收据。

### C-006 公共/适配器/负向合同和输出隔离

- 流程变更必须通过公共平台合同、项目适配器合同和系统无关负向合同测试。
- 项目输出只能写入适配器声明的目录，拒绝 `..` 路径穿越；公共平台不得把结果写回自身目录。
- 缺少不同 `applicationId` 的真实试点时，平台保持未完成；项目字段可保持 `moduleDeliveryBlocked=false`。

### C-007 实时事件

流程运行时至少写入 `run.started`、`run.authorized`、`batch.started`、`operation.started`、`operation.called`、`batch.completed` 和 `run.completed`；事件包含 `caseId、runId、applicationId、planId、operationKey、开始/结束时间、耗时、结果和重试信息`，并具备幂等和中断保留能力。

### C-008 企业治理

- 权限按角色、项目、环境和证据敏感级别控制；原始消息、敏感证据、收据、导出、确认、修复和回滚均执行授权校验。
- 查看、导出、确认、状态变更、修复、回滚、保留到期和合规删除写入不可篡改审计日志，日志包含操作者、时间、对象、动作、结果和原因。
- 历史快照、运行收据和证据定义保留、归档、合规删除和恢复策略；删除或恢复必须有独立收据。

### C-009 价值指标遥测

平台必须以脱敏遥测记录证据定位耗时、历史查找耗时、无效重跑减少、收据缺口发现、误判产品失败、根因分类耗时、有效重跑命中、人工介入和跨项目复用等指标所需事件；指标必须带分母、采样范围、更新时间和责任人，支持按 `runId/caseId` 下钻，不得以历史快照冒充实时指标。

## 3. 当前差距

| 差距 ID | 对应 FR | 当前状态 | 影响 | 完成条件 | 现有业务结果 |
|---|---|---|---|---|---|
| GAP-001 | FR-017/C-001 | 历史未证明完整覆盖 | 通过收据可能不完整 | 公共合同、适配器合同、负向测试和标准收据全部通过 | 不重跑、不失效 |
| GAP-002 | FR-018/C-002 | 历史未证明完整覆盖 | 可能在错误上下文执行 | 授权和守卫合同在业务动作前阻断错误场景 | 不重跑、不失效 |

| GAP-004 | FR-020/C-004 | 历史未证明完整覆盖 | 状态和分母可能失真 | 状态字段、守恒公式和系统无关负向测试通过 | 不重跑、不失效 |
| GAP-005 | FR-021/C-005 | 历史未证明完整覆盖 | 可能产生测试残留 | 服务端 ID、finally 清理和 UI/API 零残留收据齐全 | 不重跑、不失效 |
| GAP-006 | FR-022/C-006 | 历史未证明完整覆盖 | 项目实现可能越界复制平台能力 | 三层合同和输出隔离测试通过 | 不重跑、不失效 |
| GAP-007 | FR-023 | 有一次性修复旁证，未形成完整产品合同 | 历史修复可能不可回滚 | dry-run、备份、差异、回滚和健康检查产品化 | 不改变业务结果 |

## 5. 当前执行边界

本登记只描述差距，不自动创建开发任务，不自动启动跨应用试点，不重跑已通过业务用例。任何后续开发都必须明确目的、预期结果、后续影响和验收收据。

## 6. 平台 GA 发布门槛

公共平台只有在 C-001～C-009、系统无关负向测试、不同 `applicationId` 真实试点、企业治理（GAP-009）和用户价值指标基线（GAP-010）全部具备独立收据后，才可标记为 `GA/平台级成熟`。任一条件缺失时保持 `not-ready` 或 `deferred`；该状态不改变项目自身门禁通过结果，也不将 Merchant Center 标记为失败。
