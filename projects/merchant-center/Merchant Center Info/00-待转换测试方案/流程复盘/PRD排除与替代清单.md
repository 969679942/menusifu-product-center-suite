# PRD 排除与替代清单

版本：1.0（2026-08-29）  
用途：防止优化前探索、旧指标和被撤销结论污染现行 PRD。

| 被排除或降级内容 | 原始来源 | 处理 | 当前替代 |
|---|---|---|---|
| 侧边栏看不到即认为对话被删除 | 历史可见性问题对话 | 降级为历史问题背景 | 以 rollout 文件、归档状态和元数据健康检查判定存在性 |
| 脚本生成或请求探针通过即代表业务完成 | `019f99ff…` 等早期讨论 | 不进入通过标准 | 区分绑定、请求级验证、业务 CRUD、断言、清理和标准收据 |
| `587/587` 可直接表述为完整业务通过 | `01a005e0…` 早期口径 | 标记为已纠正 | 17 个真实 CRUD 与权限/夹具/废弃接口分开统计 |
| 测试通过自动覆盖正式业务规则 | 规则治理前的探索建议 | 排除为现行方案 | 规则指纹、审批、基线晋级和用例重验分离 |
| 旧 API 文档路径代表当前页面调用 | 接口审计前文档 | 保留为废弃旁证，不作现行事实 | 以页面网络证据和当前 endpoint 生命周期为准 |
| 所有任务总数、归档数和日期只取列表元数据 | 历史恢复早期统计 | 排除为时间线口径 | 消息级 timestamp 为主，任务元数据为辅 |
| 在线审计中心、Jenkins 自动触发已完成 | 早期规划或未接入能力 | 标记为暂缓/未完成 | 本地/CI 公共入口优先，外部接入保持 deferred |
| 未确认的助手建议 | 各历史线程中的推测性答复 | 不进入 PRD | 只有用户确认、项目证据或公共合同才能形成需求 |
| 旧账号/provider/归档状态下的可见性结论 | 历史修复前状态 | 不作为当前状态 | 以修复后健康检查和当前索引为准 |

## 排除规则

- 排除不等于删除历史；原内容仍保留在历史时间线和 rollout 文件中。
- 被排除内容不能出现在 PRD 的“系统应当”“必须通过”“当前指标”条款中。
- 若后续证据重新证明某项旧方案有效，必须新建来源、重新确认和新版本 PRD，不得直接恢复旧文字。
