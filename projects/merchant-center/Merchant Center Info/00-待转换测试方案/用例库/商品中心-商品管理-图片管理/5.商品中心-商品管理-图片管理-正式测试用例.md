# 商品中心-商品管理-图片管理正式测试用例

> 来源：`5.商品中心-商品管理-图片管理.xmind` + `商品中心业务规则.md` §18  
> **UI 口径（现网）**：进入 **商品管理 → 图片管理**；左侧 **渠道** 筛选（「全部」= 所有渠道）；渠道列表只读（DB 维护，页面无增删改）。已知渠道：POS、Kiosk、E-Menu、Online Order、Self Dine In、DoorDash、UberEats、Grubhub、熊猫外卖、饭团、Central。缩略图左下角展示所属渠道标签。能力矩阵：**附录 B.9**（72 条）。

通用前置条件：已经登录商品中心，并进入到商品中心首页。

## 图片库

### 用例编号：TC-IMG-LIB-001

用例标题：图片库默认加载-点击全部展示所有渠道图片

所属模块：商品管理 → 图片管理

优先级：P0

来源：BR-IMG-005

前置条件：
1. 已登录商品中心并进入商品中心首页。
2. 测试环境存在属于不同渠道的图片数据。

测试步骤：
1. 进入 商品管理 → 图片管理 页面。
2. 在左侧渠道区点击「全部」。
3. 查看右侧图片列表及缩略图左下角渠道标签。

预期结果：
1. 列表展示当前品牌下 **所有渠道** 的图片。
2. 各图片左下角展示其所属渠道标签；列表可向下滚动加载更多。

### 用例编号：TC-IMG-LIB-007

用例标题：图片名称在同渠道内重复时保存失败

所属模块：商品管理 → 图片管理

优先级：P0

来源：业务规则明确 ← BR-IMG-001（2026-09-05 人工确认）

前置条件：
1. 已登录商品中心并进入商品中心首页。
2. 同一可用渠道下存在名称不同的图片 A、图片 B；若当前租户页面仅展示「全部」，则在该默认渠道上下文内准备两张图片。

测试步骤：
1. 进入 商品管理 → 图片管理 页面。
2. 记录图片 A、图片 B 的名称与服务端 ID。
3. 编辑图片 B，将图片 B 的名称修改为图片 A 的名称并保存。
4. 重新查询图片 A、图片 B，并按服务端 ID 核对名称。

预期结果：
1. 保存被拒绝，页面展示图片名称重复校验提示；精确提示文案以当前页面返回为准。
2. 图片 A 保持原名称，图片 B 仍保持修改前名称，同一渠道内未新增第二条同名图片。
