# 当前发布收据资格

公共入口为 `src/governance/current-release-receipt.ts`。适配器必须独立提供当前 caseId、用例/语义/实现/执行上下文指纹、全部声明操作键、断言 ID 和清理要求。不得从待验收收据、历史通过名单或历史失败名单补集反向构造当前合同。

通过资格要求当前 4.0.0 收据与四项身份匹配；每项声明操作恰好一个已执行成功且有起止时间的明细；公共运行合同接受全部断言明细，且实际值已观测、观察通道与权威匹配、比较成功。收据声明的 required/observed/verified 集合必须等于当前断言集。要求清理的用例必须具备 API/UI 相同对象集合的零残留观测，布尔自报不能代替明细。内容指纹必须与收据内容一致。

`readPlaywrightRuntimeReceiptCandidates` 只读取原始最近执行尝试，不授权通过。它保留最新失败、无效时间及重复收据造成的不确定性，不能回退旧成功；它返回原报告内容哈希。项目发布必须把该哈希纳入来源链。

公共负向合同覆盖历史摘要、缺失收据、身份及上下文漂移、重复操作、缺实际值、比较不匹配、清理布尔自报和对象集合不一致。项目适配负向合同还须覆盖最新失败、重复附件、路径越界和实际发布入口缺少当前合同。

报告治理修复不启动业务重跑，也不删除或重写历史事实。当前通过资格不足时必须登记当前缺口；技术合同映射缺口由执行代理补齐，不转交人工。
# 纯排版实现等价

报告适配器可以在原始实现哈希不同的情况下调用公共 `verifyImplementationFormatEquivalence`。它以收据合同已冻结的原始指纹为锚，核验完整依赖集合、分类及每个旧文件哈希；变化的 TypeScript 文件必须提供项目内原字节快照。当前和快照均解析成功，完整语法树、叶子标记、注释和 shebang 一致，且读取结束后当前指纹仍一致，才接受纯排版等价。

证据缺失、快照哈希不符、依赖增减、配置变化、表达式/常量/字符串/注释变化、自动分号差异、越界路径均拒绝。等价不修改原收据、原始指纹或运行时间；用例、上下文、操作、断言、清理和最近尝试仍通过原公共收据合同。它不支持相邻方法的代码修改，也不以新算法静默升级历史收据。

该能力用于避免纯排版导致业务重复运行。采用者须独立登记完整旧检查点与快照，并在每次报告消费时重新验证，不接受上次的布尔结论。
